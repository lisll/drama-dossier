# 素材与报审包规格

## v1 输入扫描规则

1. 用户选择一个素材根目录。
2. 素材根目录下每个非隐藏子目录视为一部剧。
3. 剧目目录中的视频和元数据文件会被读取；一层子目录也会被扫描。
4. 视频扩展名：`mp4`、`mov`、`mkv`、`flv`、`ts`、`m4v`、`webm`。
5. 图片扩展名：`jpg`、`jpeg`、`png`、`webp`。
6. 文本扩展名：`txt`、`md`。

集号解析优先级：

1. `第12集`、`第12话`、`第12回`（文件名里任意位置，取第一个成立的：`第2季第3集` → 3）
2. 词边界形式的 `E12`、`e03`、`EP12`，或季集写法 `S01E05`（→ 5）
3. 文件名主干中的独立数字，如 `show_12`，取最后一个 1–9999 的数字段；分辨率、帧率与编码标记不算
   （`1080p`、`1080i`、`4K`、`60fps`、`1920x1080` 两侧、`x264` / `h265`），全部被排除时退回取最后一个数字

集号相同的分集按文件名、再按完整路径排序。

## v1 检查规则

下表是内置默认值；都可在界面的「检查规则与路径设置」中覆盖，并随设置保存到本机配置文件（应用配置目录下的 `settings.json`）：

| 项目 | 默认规则 | 级别 |
|---|---:|---|
| 分集数量 | 少于 4 集警告，0 集失败 | warn / fail |
| 单集时长 | 31–480 秒之外警告 | warn |
| 码率 | 超过 8 Mbps 建议规范化 | warn |
| 画幅 | 高大于宽为建议竖屏 | warn |
| 封面 | 缺失失败 | fail |
| 简介 | 缺失失败，少于 30 字警告，文件读不出警告 | fail / warn |
| 集号 | 有重复集号或中间缺号时警告（不拦截） | warn |
| 分集规格 | 探测失败为失败；读不到时长 / 分辨率 / 码率时警告，不按 0 判定 | fail / warn |

`ready` 只表示没有失败项；警告仍应由人工确认。

## v1 报审包结构

```text
报审包/
├── 01_剧集信息/
│   ├── 剧名.txt
│   └── 简介.txt
├── 02_封面海报/
│   └── 封面.jpg
├── 03_分集清单/
│   └── 分集清单.csv
├── 04_成本配置表/
│   └── 成本配置表.md
├── 05_权属声明/
│   └── 内容权属声明.txt
├── 06_分集视频/
│   └── 第01集.mp4
├── 07_证明与过程图/
│   ├── AI制作证明.png
│   ├── 过程图_01.png … 过程图_04.png
│   └── 剧目海报.png
└── manifest.json
```

`06_分集视频` 仅在勾选「复制分集视频进报审包」时生成。

`07_证明与过程图` 在勾选「带上 AI 制作证明与过程图」（默认勾选）且深度处理输出目录里确实有这些文件时生成：
只放实际存在的文件（证明优先 `AI制作证明.png`，没有时用 `AI制作证明.txt`；过程图只收存在的编号；剧目海报按
`剧目海报.<png|jpg|jpeg|webp>` 取第一张）。一个都没有时不建这个目录，原因写进 `manifest.json` 的
`proofSource.note`。

「标准文件」清单（覆盖旧包时「只替换标准文件」模式的依据，也只有这些名字的文件会被当作本程序产物清理）：

```text
manifest.json
01_剧集信息/剧名.txt、01_剧集信息/简介.<任意扩展名>
02_封面海报/封面.<任意扩展名>
03_分集清单/分集清单.csv
04_成本配置表/成本配置表.md
05_权属声明/内容权属声明.txt
06_分集视频/第NN集.<任意扩展名>（NN 至少两位），重复集号另有 第NN集-<序号>.<扩展名>
07_证明与过程图/AI制作证明.png|txt、过程图_NN.png（两位编号）、剧目海报.<任意扩展名>
```

不在这张名单里的文件（例如使用者自己放进包的说明、花絮视频、改名后的旧证明）不会被「只替换标准文件」删除。

包内命名规则（扩展名一律跟原文件）：

- `简介.<原扩展名>`（`txt` / `md`）、`封面.<原扩展名>`（`jpg` / `png` / `webp` 等）；
- 分集 `第NN集.<原扩展名>`，NN 位数取 max(2, 最大集号位数)；解析不出集号的分集保留原文件名；
- 重名（重复集号或撞上已有名字）时按（有集号在前、集号、完整路径）的固定顺序给后来者加 `-2`、`-3`……，
  比较不区分大小写；
- `分集清单.csv` 带 UTF-8 BOM，单元格做公式注入防护（以 `=`、`+`、`-`、`@` 等开头时加英文单引号），
  末列「包内文件名」对应 `06_分集视频/` 里的文件名（未复制分集时为空）。
- 任何一集探测失败时拒绝生成并列出失败的分集，不会生成缺集的报审包。

## 覆盖旧包

目标目录已存在时默认不生成，等使用者确认。确认后由 `PackageOptions.overwrite` +
`overwriteMode` 决定做法：

- `replaceAll`（默认，整体替换）：旧包整体改名为同级备份 → 新包就位 → 删备份。旧包里的文件（含使用者
  自己放进包里的）全部被替换；报告里的 `dropped` 是旧包被换掉的文件数。
- `standardOnly`（只替换标准文件）：逐个覆盖上表「标准文件」中的路径，旧包里**不在**名单里的文件原地保留
  （报告里的 `kept`），名单里但本次不再生成的路径会被删掉（报告里的 `removed`）。
  代价：如果使用者把旧文件改成非标准名字留在包里，可能残留过期文件。

两种模式都保证任一步失败时，正式目录要么是完整的旧包，要么是完整的新包；安全闸会拒绝把剧目目录本身
或磁盘根目录当作旧包替换。

## manifest.json

字段（camelCase，`schema` 与 `sha256` 保持不变）：

```json
{
  "schema": "drama-dossier/package@1",
  "dramaName": "示例短剧",
  "generatedAt": "2026-10-13T20:00:00Z",
  "aiGenerated": false,
  "copyEpisodes": false,
  "files": [
    {
      "path": "01_剧集信息/剧名.txt",
      "sizeBytes": 128,
      "sha256": "..."
    }
  ]
}
```

`files` 只列出写入报审包的文件（不含 `manifest.json` 自身）；`sha256` 为小写十六进制。

新增两个字段（向后兼容，`schema` 不变；读清单的工具不认识这两个字段时忽略即可，`diff` 对比不受影响）：

- `proofFiles`：收进 `07_证明与过程图/` 的文件，结构同 `files`（这些路径同样会出现在 `files` 里，
  这里单列一份方便平台与核对工具直接取用）。没有收进任何证明时为 `[]`。
- `proofSource`：证明材料的来源与「为什么没有」。`dir` 是读取的深度处理输出目录；
  `note` 是没放进包时的原因（未勾选 / 没找到目录 / 目录里没有这些文件）。收齐时不写这一项。

`manifest.json` 是本地完整性清单，不是官方审核回执，也不能替代任何公章、签名或可信时间戳。

`dossier-core::diff` 直接读这份清单做改稿对比：逐文件给出「新增 / 移除 / 修改 / 未变」
与大小变化，并且只比对清单里登记的相对路径、大小与 SHA-256——**不会去读素材内容**。
未变的文件不进明细列表，只计入汇总，避免改一版就刷出一屏噪声。

## 平台材料要求（示例档案）

`dossier-core::platforms` 内置了少量**学习示例**档案（竖屏短剧 / 横屏长剧 / 预告切片 /
通用兜底），说明「一个投放形态通常关心哪些字段」：容器与编码、时长区间、竖屏方向、
短边下限、码率上限，以及封面、简介、分集清单、成本表、权属声明这几类材料。

这些数值来自公开的行业惯例，**不是任何平台的官方规范**，也不构成合规意见；
接入真实业务前必须替换为平台方最新的投稿规范。模块是纯查表 + 对照本地探测结果的函数，
不联网、不抓取平台页面。

## 权属声明模板

报审包固定包含权属声明模板，要求使用者填写素材来源、授权状态和联系人。模板只是提示使用者履行确认义务，不生成法律效果，也不改变材料的真实性责任。

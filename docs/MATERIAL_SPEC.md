# 素材与报审包规格

## v1 输入扫描规则

1. 用户选择一个素材根目录。
2. 素材根目录下每个非隐藏子目录视为一部剧。
3. 剧目目录中的视频和元数据文件会被读取；一层子目录也会被扫描。
4. 视频扩展名：`mp4`、`mov`、`mkv`、`flv`、`ts`、`m4v`、`webm`。
5. 图片扩展名：`jpg`、`jpeg`、`png`、`webp`。
6. 文本扩展名：`txt`、`md`。

集号解析优先级：

1. `第12集`、`第12话`、`第12回`
2. 词边界形式的 `E12` 或 `e03`
3. 文件名主干中的独立数字，如 `show_12`

## v1 检查规则

下表是内置默认值；都可在界面的「检查规则与路径设置」中覆盖，并随设置保存到本机配置文件（应用配置目录下的 `settings.json`）：

| 项目 | 默认规则 | 级别 |
|---|---:|---|
| 分集数量 | 少于 4 集警告，0 集失败 | warn / fail |
| 单集时长 | 31–480 秒之外警告 | warn |
| 码率 | 超过 8 Mbps 建议规范化 | warn |
| 画幅 | 高大于宽为建议竖屏 | warn |
| 封面 | 缺失失败 | fail |
| 简介 | 缺失失败，少于 30 字警告 | fail / warn |

`ready` 只表示没有失败项；警告仍应由人工确认。

## v2 报审包结构（服务端生成文档，桌面端组装）

现在生成报审包**必须联网**，账号要有有效使用权。桌面端只把剧目信息、成本表单、分集与封面 / 简介的
**文件名、大小、SHA-256 与探测规格**发给服务端——视频、封面、简介本身都不上传。服务端生成文本文件、
把两份需要盖章的文档渲染成 PDF 并盖章、给清单签名；桌面端验签后把本机文件放进包里的对应位置，
再逐个重算哈希比对，对不上就拒绝，不留半个目录。

包内路径以 `dossier-core::package::render_documents` 的产出为准：

```text
报审包/
├── 01_剧集信息/
│   ├── 剧名.txt                    # 服务端生成
│   └── 简介.txt                    # 本机文件，文件名照原样
├── 02_封面海报/
│   └── 封面.jpg                    # 本机文件，文件名照原样
├── 03_分集清单/
│   └── 分集清单.csv                # 服务端生成
├── 04_成本配置表/
│   ├── 成本配置表.md               # 服务端生成
│   └── 成本配置表_未签署.pdf       # 服务端生成并盖占位章
├── 05_权属声明/
│   ├── 内容权属声明.txt            # 服务端生成
│   └── 内容权属声明_未签署.pdf     # 服务端生成并盖占位章
├── 06_分集视频/                    # 仅勾选「复制分集视频进报审包」时生成
│   └── 第01集.mp4                  # 本机文件
├── manifest.json
└── manifest.sig
```

- 封面与简介的文件名沿用本机原名，只是被放进 `02_封面海报` / `01_剧集信息` 目录；放进去的分集同理，
  落在 `06_分集视频` 下。服务端生成的文本文件与这些本机文件**不许撞名**（例如简介文件恰好叫「剧名.txt」），
  撞了直接报错；清单里所有 `files` 的路径还会按不区分大小写再查重一次。
- 两份需要盖章的文档（`04_成本配置表/成本配置表.pdf`、`05_权属声明/内容权属声明.pdf`）由
  `render_documents` 给出**排版模型**（标题、表格行、段落、签章位坐标），服务端只负责画成 A4 PDF、
  在签章位上盖章，不自己拼文字；正文写到 `contentBottomMm`（200 毫米）为止，写超了就报错，不让正文压到章上。
- **占位章**（M4a 桌面端固定用 `signer: mock`）：每个签章位画灰色虚线框、框内写
  「样章 · 未签署 / 无法律效力」（签名位写「签名占位 / 未签署」），整页加「草稿 · 未签署」斜向水印；
  文件名在 `.pdf` 前插入 `_未签署`，清单里 `signature.placeholder` 为 `true`。
  **不画红色圆章**：逼真的假章一旦流出就可能被当成真章使用。
  正式报审前必须换成盖章版本（服务端也支持上传整页盖章扫描件的 `signer: scan`，此时文件名不带 `_未签署`）。
- 不勾选「复制分集视频」时：分集只登记在 `references` 里，不进包；组装时仍会把每集读一遍重算哈希，
  和提交时发上去的值比对。
- 一部剧最多 **500** 集；剧名最长 200 个字符，且必须能当文件名用（不含 `/` 和文件名保留字符）。
  分集的 `file_name` 不许重复（不区分大小写）。
- 组装先写与正式目录同级的临时目录（`.<目录名>.partial-<pid>-<纳秒>`），全部对上才改名为正式目录；
  中途失败删掉临时目录，**不留半个包**；目标目录已存在时直接拒绝。

## manifest.json

清单由服务端生成并用 Ed25519 签名，签名另存在 `manifest.sig`；桌面端组装前先验签。

### 清单格式 `drama-dossier/package@2`

字段（camelCase，多一个不认识的字段整份拒绝）：

```json
{
  "schema": "drama-dossier/package@2",
  "packageId": "0f6c1e2a-…",
  "generatedAt": "2026-10-15T15:00:00+00:00",
  "userId": "…",
  "deviceId": "…",
  "dramaName": "示例短剧",
  "aiGenerated": false,
  "copyEpisodes": false,
  "signature": {
    "signer": "mock",
    "placeholder": true,
    "documents": ["04_成本配置表/成本配置表_未签署.pdf", "05_权属声明/内容权属声明_未签署.pdf"]
  },
  "files": [
    {"path": "01_剧集信息/剧名.txt", "sizeBytes": 12, "sha256": "…", "source": "server"},
    {"path": "02_封面海报/封面.jpg", "sizeBytes": 204800, "sha256": "…", "source": "local"}
  ],
  "references": [
    {"path": "第01集.mp4", "sizeBytes": 10485760, "sha256": "…"}
  ]
}
```

| 字段 | 含义 |
|---|---|
| `schema` | 固定 `drama-dossier/package@2`；不是这个值按「内容无法识别」处理 |
| `packageId` | 服务端生成的报审包 ID（UUID），和 `packages` 表里的一行对应 |
| `generatedAt` | 生成时间（数据库时间的 ISO 8601 字符串） |
| `userId` / `deviceId` | 账号 ID / 机器码；`deviceId` 必须等于本机机器码 |
| `dramaName` | 剧名（去掉首尾空白） |
| `aiGenerated` / `copyEpisodes` | 是否 AI 辅助生成 / 是否复制分集视频进包 |
| `signature.signer` | 签章方式：`mock`（占位章）/ `scan`（上传的盖章扫描件） |
| `signature.placeholder` | `true` 表示用的是占位章，不具法律效力 |
| `signature.documents` | 用了占位章、带 `_未签署` 后缀的文档路径，必须是 `files` 里出现过的路径 |
| `files` | 包里真正有的文件，**不含** `manifest.json` / `manifest.sig` 自身 |
| `references` | 不复制进包、只登记哈希的分集 |

`files` 和 `references` 的区别：`files` 是要真的写进包里的（服务端发回的文档 + 桌面端从本机放入的
封面、简介、复制进包的分集），组装时逐字节重算大小与 SHA-256 比对；`references` 是**留在剧目目录里**的
分集，只登记剧目目录内的文件名、大小与哈希，组装时只复核算一遍，不复制、不移动。

`source` 只有两个取值：`server` 表示服务端发回的文档，`local` 表示桌面端从本机放入。
服务端发回的文件必须与 `source: server` 的条目一一对应，多一个少一个都拒绝。

校验规则：`files` 的 `path` 必须是安全的相对路径——非空、最长 512 字节、不以 `/` 开头、用 `/` 分隔，
每段不许为空、不许是 `.` 或 `..`、不许以 `.` 或空格结尾，整条路径不许出现 `\` `:` `*` `?` `"` `<` `>` `|`
和控制字符；并按**不区分大小写**去重。`references` 的 `path` 只许一段文件名，不许带目录。
`sha256` 一律是 64 位小写十六进制；`packageId` / `userId` / `deviceId` 不许为空。

### manifest.sig

```json
{"kid": "9f86d081884c7d65", "sig": "<base64url 签名>"}
```

- 签的对象是 **`manifest.json` 的原始字节**：组装时把这两个文件原样写回包里，重新序列化就验不过了。
- 算法 Ed25519，签名对象是固定前缀 `"drama-dossier/package-manifest/v1\n"` 拼上 `manifest.json` 原始字节。
  `sig` 是 base64url（不带填充），解码后必须正好 64 字节；逐把受信公钥尝试，返回实际验过签的那把的指纹。
- `kid` 只是提示，以实际验过签的公钥为准；签名文件里写的 `kid` 和实际对不上，按签名无效
  （`bad_signature`）处理。
- **用途前缀隔离**：同一把服务端私钥签三种东西，前缀各不相同——授权凭证 `drama-dossier/license/v1\n`、
  报审包清单 `drama-dossier/package-manifest/v1\n`、处理配方 `drama-dossier/recipe/v1\n`。
  用授权凭证的签名来验清单（或反过来）都会失败。

验签顺序：签名文件格式 → 签名 → 清单内容 → 机器码，哪一步不过就停在哪一步，错误码分别是
`malformed` / `bad_signature` / `bad_payload` / `wrong_device`。

`manifest.json` 是完整性清单，不是官方审核回执，也不能替代任何公章、签名或可信时间戳。

### 与旧包对比

旧的 `drama-dossier/package@1` 包（本机生成、只有 `schema` / 剧名 / 生成时间 / AI 标记 / 复制标记 /
`files`，没有 `references`、`signature` 和 `manifest.sig`）**仍然能做差异对比**：
`dossier-core::diff` 也只读 `files` 里的 `path` / `sizeBytes` / `sha256`，新字段它会忽略。

`dossier-core::diff` 直接读清单做改稿对比：逐文件给出「新增 / 移除 / 修改 / 未变」
与大小变化，并且只比对清单里登记的相对路径、大小与 SHA-256——**不会去读素材内容**。
未变的文件不进明细列表，只计入汇总，避免改一版就刷出一屏噪声。

## 平台材料要求（示例档案）

`dossier-core::platforms` 内置了少量**学习示例**档案（竖屏短剧 / 横屏长剧 / 预告切片 /
通用兜底），说明「一个投放形态通常关心哪些字段」：容器与编码、时长区间、竖屏方向、
短边下限、码率上限，以及封面、简介、分集清单、成本表、权属声明这几类材料。

这些数值来自公开的行业惯例，**不是任何平台的官方规范**，也不构成合规意见；
接入真实业务前必须替换为平台方最新的投稿规范。模块是纯查表 + 对照本地探测结果的函数，
不联网、不抓取平台页面。

## 权属声明模板

报审包固定包含权属声明模板，要求使用者填写素材来源、授权状态和联系人。模板只是提示使用者履行确认义务，不生成法律效果，也不改变材料的真实性责任。

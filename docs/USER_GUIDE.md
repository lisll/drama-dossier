## 1. 这是什么

剧备是一个**本地优先**的桌面应用：素材、检查报告、生成结果全部留在你自己的电脑上，不注册账号、
不上传素材、不做云端同步。

它帮你把这几件重复劳动自动化：

1. 按约定扫描本机的剧集素材目录，认出「一部剧 = 一个子目录」；
2. 调用本机 `ffprobe` 读取每一集的时长、分辨率、编码、帧率、码率；
3. 按可解释的规则给出检查结论（哪些缺失、哪些需要人工确认）；
4. 生成编号清晰的报审包目录 + 本地完整性清单 `manifest.json`；
5. 附带一个后期工具箱（改名、码率修复、转码、差异对比、草稿交接、字幕/角标擦除）。

**它不做什么**：不代你填真实信息、不伪造签名/印章/时间戳、不替代平台审核、不绕过任何版权保护。
规则里的阈值与「平台档案」都是**学习示例**，接入真实业务前必须换成平台方最新规范。

## 2. 装好之后先做一次环境自检

剧备自己不含视频工具，需要本机有 **FFmpeg（必须包含 `ffprobe`）**。可以自己装，也可以让应用帮你装。

- 启动后，如果缺少工具，窗口**顶部**会出现一条**运行环境横幅**，上面直接带「一键配置运行环境」按钮：
  点一下会自动下载安装 `ffmpeg` / `ffprobe`（约 25 MB，需要联网），装好后路径自动写入设置并重新检测；
  环境就绪后横幅自动隐藏，不再占版面。**不用等你点了按钮才发现跑不通。**
  - 该按钮**目前仅在 macOS 上出现**（下载 evermeet.cx 的官方构建，会用到系统自带的 `curl` 与 `unzip`）。
    Windows / Linux 上**不会**显示这个按钮，横幅与「设置 → 本机环境」会改成给出对应平台的手动安装命令：
    Windows 用 `winget install Gyan.FFmpeg`（或到 gyan.dev 下载后把 `bin` 加入 `PATH`），
    Linux 用 `sudo apt install ffmpeg` / `sudo dnf install ffmpeg`。
  - Apple 芯片（Apple Silicon）首次使用若提示 CPU 架构不匹配，请先在终端执行
    `softwareupdate --install-rosetta --agree-to-license` 安装 Rosetta 2，再重新点击一键配置。
- 窗口右上角另有一个**常驻环境标签**，随时反映状态：
  - `本机环境就绪`（绿）：可以正常扫描、探测、生成；
  - `缺少 ffmpeg` / `缺少 ffprobe`（红）：还没找到，点一下跳到「设置 → 本机环境」看详情；
  - `环境异常：ffmpeg / ffprobe`（黄）：找到了但不可用（例如路径指向了别的程序），同样点标签查看。
- 「设置 → 本机环境」里除了「一键配置运行环境」，还有「重新检测」，以及一个高级项
  「ffprobe 路径」（例如 `/opt/homebrew/bin/ffprobe`、`C:\ffmpeg\bin\ffprobe.exe`）。
  **留空时**应用按「设置里的路径 → 安装目录 → 系统 `PATH`」的顺序自动查找。

缺 FFmpeg 时仍然能做的事：**扫描剧目**（只读文件名与体积）。会失败的事：**探测并检查**、
生成报审包、码率修复、执行转码。注意「一键配置运行环境」是应用里**唯一**会联网的动作，
且只下载官方的 ffmpeg 压缩包。

## 3. 界面总览

界面是一列左侧导航 + 四块工作区，任何时刻只显示一块：

| 区域 | 作用 |
| --- | --- |
| 剧目库 | 选素材根目录 → 扫描 → 点选一部剧 → 探测并检查 |
| 生成报审包 | 填写出品方、投资额等信息并生成报审包 |
| 工具箱 | 改名、码率修复、转码、报审包对比、平台档案、剪映草稿、擦除 |
| 设置 | 检查规则阈值、默认路径、本机环境、关于 |

界面顶部还有这几样东西：

- **运行环境横幅**：只在缺少 `ffmpeg` / `ffprobe` 时出现，装好即隐藏。macOS 上带「一键配置运行环境」
  入口，其他平台改为直接给出该平台的手动安装命令；
- **常驻环境标签**（右上角）：随时显示「本机环境就绪」或缺哪个工具，点一下跳到「设置 → 本机环境」；
- **当前剧目**标签：提醒你现在所有操作都作用在哪一部剧上；
- **进度条**：所有耗时操作都会显示。逐集探测能算出总量时是**确定进度**（`正在探测分集 3/12：第03集.mp4`），
  转码与码率修复按「第 3/8 集」这类单元显示确定进度；擦除按「第几段 + 已完成多少帧」显示确定进度
  （`擦除中 · 逐片段修复画面（第 2/2 段）：已完成 1234/5000 帧`）。
  真的算不出总量时才退回**不确定进度 + 已用秒数**；
- **提示条（Toast）**：失败用红色并统一带「出错了：」前缀，停留时间也更长（9 秒，成功为 4.5 秒）。
  除了颜色还有文字前缀，截图或投屏也能分辨成功与失败。
  路径、权限、运行环境这类**能指出下一步**的错误会直接带一个按钮（「打开设置」/「重新检测」/
  「去设置环境」），点了就跳过去，不用自己翻页找。

**长任务只允许一个**：只要有任务在跑（扫描、探测、生成、改名、码率检测/修复、转码、平台对照、
草稿读写、擦除），所有耗时按钮都会自动置灰，避免重复点击把同一件事跑两遍。想再点会提示
「已经有任务在进行」。

## 4. 五分钟上手

1. 打开应用 → 左侧「剧目库」。首次进入时中间会有一份**三步引导**（选择目录 → 扫描剧目 →
   点选剧目并探测），每完成一步前面的圆圈会打勾，也可以直接点引导里的按钮走完，不必自己找入口。
2. 在「素材根目录」里输入或点「选择」挑一个目录（里面每个子目录 = 一部剧）。
   扫描成功后这个路径会**自动记住**，下次启动直接回填。
3. 点「扫描剧目」，左侧会列出找到的剧目与集数、总体积。
4. 点选一部剧 → 点右上角「探测并检查」，等待进度条走完。
5. 看「检查结果」（通过 / 需确认 / 不通过）和「分集」表，按提示补齐缺失材料。
6. 切到「生成报审包」，填出品方等信息 → 点「生成材料包」。
7. 生成完可以点结果里的「打开目录」直接跳到报审包，或「复制路径」发给同事。

## 5. 素材怎么准备

推荐的目录结构（根目录下每个子目录是一部剧）：

```text
素材根目录/
└── 示例短剧/
    ├── 第01集.mp4
    ├── 第02集.mp4
    ├── 封面.jpg
    └── 简介.txt
```

- 视频扩展名：`mp4`、`mov`、`mkv`、`flv`、`ts`、`m4v`、`webm`；
  图片：`jpg`、`jpeg`、`png`、`webp`；文本：`txt`、`md`。
- 剧目目录内部的**一层子目录**也会被扫描。
- 集号解析优先级：① `第12集` / `第12话` / `第12回`（`第2季第3集` 取 3）→ ② 词边界的 `E12` / `e03` / `EP12`，
  以及季集写法 `S01E05` → ③ 主干里的独立数字（`show_12`），取最后一个；分辨率、帧率与编码标记不算集号
  （`1080p`、`4K`、`60fps`、`1920x1080`、`x264` / `h265`），所以 `剧名_12_1080p` 解析为 12。
  解析不出集号的文件会被列入「无法解析」并保持不动（不会乱改名）。
- 集号相同的分集按文件名、再按完整路径排序，顺序固定。多季混放在同一目录时 `S01E05` 与 `S02E05`
  都会解析为 5，检查结果会提示「集号重复」。
- 封面建议 `封面.jpg`，简介建议 `简介.txt`，不少于 30 字，写清题材、主要人物、受众定位。

> 小贴士：文件名不统一时，先去**工具箱 → 批量改名**把它统一成「剧名 - 第NN集」，
> 再做探测与生成——集号解析依赖文件名。

## 6. 模块一：剧目库

### 扫描剧目

- 输入/选择根目录 → 「扫描剧目」。找不到子目录时会显示「未找到剧目子目录。」。
- 左侧剧目条目显示：剧名、集数、素材总体积。
- **切换剧目或重新扫描会作废工具箱里上一部剧的计划与结论**，防止拿旧计划点执行。

### 探测并检查

点「探测并检查」后逐集读取规格，结果分两块：

- **检查结果**：每条给出「项目 + 状态 + 说明」。状态含义：
  `通过` / `需确认`（警告，需要人工判断）/ `不通过`（缺失等失败项）。
  右上角徽标是总览：`材料可用`（无失败项）或 `有缺失项`。
  - 某集**规格读取失败**（探测出错）判为 `不通过`，与生成报审包时的拒绝一致；原因看分集表那一行。
  - 探测成功但读不到时长、分辨率或码率时，对应项提示「读不到…，请人工确认」，不会误报成「低于下限」。
  - 简介文件读不出（例如不是 UTF-8 文本）时提示「简介文件无法读取」，不会按 0 字报「过短」。
  - 集号有重复或中间缺号时多一条「集号」警告，列出重复与缺少的集号；不拦截生成。
- **分集**表：集号、文件名、时长、`宽×高`、状态。探测失败的那一行直接显示失败原因。

`材料可用` 只代表**没有失败项**，警告项仍然要人工确认。

## 7. 模块二：生成报审包

上半部分是「本次运行覆盖」，只影响这一次；长期默认值在「设置」里。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 输出目录（本次覆盖） | 否 | 留空 = 按「设置 → 默认输出目录 / 剧名 / 报审包」落盘，设置也为空时才写到「剧目目录/报审包」。填了就生成到你指定的目录 |
| 出品 / 公司 | 否 | 写进报审包的成本表与权属声明；请填**真实**信息 |
| 投资总额（万元） | 否 | 必须是不小于 0 的数字，格式错误会在输入框下就地标红 |
| 演员成本占比（%） | 否 | 必须在 0–100 之间 |
| 联系方式 | 否 | 仅写入本地报审包 |
| 复制分集视频进报审包 | 否 | 勾选后会额外生成 `06_分集视频/`（最耗时的一步，进度条会说明） |
| 使用了 AI 辅助生成 | 否 | 如实勾选，会记进 `manifest.json` 的 `aiGenerated` |

这一页**不再单填 ffprobe 路径**：读取规格用的 `ffprobe` 统一取「设置 → 本机环境」里的配置
（留空则自动查找）。

点「生成材料包」后：会**先重新探测一遍**（避免用过期规格），再写报审包，最后结果里给出位置、
文件数与总大小，并提供「打开目录 / 复制路径」。

几点须知：

- 目标目录**已存在**时会直接拒绝，提示「报审包目录已存在」，不会覆盖已有材料。
  这时结果区会直接给出旧包位置，可以点「打开目录」先确认；提示条上还有「换个输出目录」按钮，
  点一下就能重新挑目录再生成（旧目录始终不会被改动）。
- 生成失败时结果区用红色展示，不会与成功色混淆。
- 报审包结构与 `manifest.json` 字段见[附录 A](#附录-a报审包目录结构)与 [`MATERIAL_SPEC.md`](MATERIAL_SPEC.md)。

## 8. 模块三：工具箱

工具箱顶部有一张「该用哪个工具？」引导卡，先按它选工具：

| 你的目标 | 用哪个 |
| --- | --- |
| 只想先看看要改什么 | 视频转码 → **转码建议**（只出建议，不动文件） |
| 只是码率不达标 | **码率修复**（会就地重编码，**替换原文件**） |
| 要改时长、顺序或分集数 | 视频转码 → **执行转码**（输出到新目录） |
| 文件名不统一 | **批量改名**（集号解析依赖文件名） |

工具卡片默认折叠，点标题展开。除改名与码率修复外，其余工具都会**另写新目录**，不动原素材。

### 8.1 批量改名

- 「预览改名计划」：列出每集的当前文件名 → 目标文件名（规则：`剧名 - 第NN集`）与状态
  （`待改名` / `已合规`）；解析不出集号的文件会单列为「无法解析、保持不动」。
- 预览是**必须的第一步**：没有计划，「应用改名」是灰的。
- 目标名冲突或重复时**整体拒绝**，不会改到一半。Windows / macOS 默认不区分大小写，所以只差大小写的两个
  目标名也算冲突；目标名含 `\ / : * ? " < > |`、以点或空格结尾、是 `CON` / `NUL` 等系统保留名时同样拒绝。
- 改名分两步执行：先把所有文件改成临时名，再统一改成新名，所以互换名字（A↔B）、整体顺延编号都能做。
  任何一步失败都会自动改回原名；万一某个文件撤销不了（例如被其他程序占用），结果里会列出它现在叫什么。
- 应用成功后旧计划立即作废，再点需要重新预览。改名后建议回「剧目库」重新扫描并检查。

### 8.2 码率修复

- 先设码率区间「下限 / 上限（Mbps）」（默认 4 / 8）→ 点「检测码率」，逐集给出**视频轨**码率与
  `在区间内 / 低于下限 / 高于上限 / 探测不到码率`。读不到视频轨码率时按「文件码率 − 音频码率」估算，
  并标「估算」。探测失败的分集也列在表里，状态栏写明失败原因。有超出区间的分集时「修复不达标分集」才会亮起。
- **只支持 mp4 / m4v / mov 封装**：修复后的文件按原容器（mp4 或 mov）封装、扩展名不变。mkv、ts、flv、webm
  等分集不会被重编码，在结果里列为失败（「码率修复暂只支持 mp4 / m4v / mov 封装」），原文件不动；
  请先用其他工具转成 mp4 再修复。
- 偏低的修到「下限 + 0.5 Mbps」（默认 4.5），偏高的压到上限（默认 8）。
- 点修复会先弹出**二次确认**，写清「即将重编码 N 集、原文件会被替换、没有备份、不能撤销」，并列出前几个文件名。
- 只重新编码视频轨，音轨与字幕轨原样保留（多音轨也都在）。原音轨 / 字幕格式放不进 mp4 / mov 时，会把音轨转成 AAC、
  字幕转成 mov_text；字幕实在放不进时去掉字幕轨。这些处理会写在该集的结果里。
- 修复走「临时文件 → 探测码率与时长 → 都合格才替换」：码率要落在区间内，**时长也要与原片一致**
  （误差不超过 0.5 秒或 1%），否则保留原文件并列为失败。但**仍然没有备份**，重要素材请先自行备份。
- 第一遍不在区间会按偏差修正目标重编一次（每集最多编码两遍），第二遍的目标不会超过上限。画面细节太少（如大片纯色）的分集
  编不到下限时**保留原文件**，原因写明「画面复杂度过低」；应用不会用填充数据凑码率。
- 执行中可以点「停止码率修复」：当前这一集立即终止、原文件不动，已替换的分集保留，剩下的不再处理。
  它只停码率修复，不影响正在进行的转码。
- 结束后给出每集「原码率 → 新码率」，失败项单列原因。结果已变化，需重新「检测码率」。

### 8.3 视频转码

**转码建议与批量规范化**（只建议，不自动执行）

- 填目标容器、码率上限（Mbps）、最大宽/高（0 表示不限）→「生成转码建议」。
- 输出：共几集、需转码几集、已合规几集；需转码的逐集给出**原因**；下面可展开查看批量 `ffmpeg` 脚本预览。
  探测失败的分集不纳入建议，单独列出文件名与原因；全部探测失败时直接报错并列出原因。
- 它给出的输出目录是预览值（剧目目录下的 `规范化/`），这一步不会写任何文件。

**执行转码**（会真的跑，耗时较长）

- 三种模式都要求**每一集都探测成功**：有任何一集探测失败就不开始，并列出失败的文件与原因
  （重组 / 深度处理少一集内容就断；智能微调的输出之后会拿去生成报审包，缺集不易发现）。
  以前智能微调会跳过坏集、其余照常处理，现在改为整批拒绝。
- 智能微调沿用原文件名与扩展名输出，开始前还会检查两件事，任一不满足就整批拒绝：
  - 不支持 webm 素材（webm 装不下 H.264 / AAC），请先转成 mp4，或改用分集重组 / 深度处理（输出 mp4）；
  - 不同子目录里有**同名**分集时会互相覆盖，请先把其中一个改名（「批量改名」只处理剧目目录本层的文件）。
  - 已知限制：mkv 原片带图形字幕（PGS / VobSub）时智能微调可能失败，ffmpeg 会明确报错，不会损坏文件。

- 「深度处理」把两件事串起来：先按场景切点把全剧重新分集（重组），再对每个新集裁掉开头
  1~3 帧（微帧），最后统一编码到新目录。
- 重组按「设置 → 生成设置 → 转码设置」里的单集时长区间规划，区间指的是**成片**时长：开了去重配方时
  会把逐集变速算进去。素材总时长无法在区间内均分时，按最接近的方案切，并在完成说明里提示。
  单集时长的下限按 5–3595 秒、上限按「下限 + 5」–3600 秒取值；上限不大于下限时按「下限 + 5 秒」处理。
  按目标集数重组、而素材只够切出更少的集时，完成说明会写「素材只能切成 N 集（目标 M 集）」。
- 去重配方里的旋转是肉眼几乎看不出的微旋转（每集最多约 2°），为遮住旋转露出的黑角只裁掉
  约 6% 的边缘。0.2.24 及更早版本把这个角度单位用错了，成片会明显歪斜并只剩中间约一半画面；
  修复后的配方存证文件标记为 `drama-dossier/dedup-recipe@2`（含 `"rotationUnit": "degrees"`），
  旧的 `@1` 存证与新版本编出的画面不同，不能用新版本复算。
- 开着「AI 合规角标」时，角标在任何编码开始前先生成；生成失败（例如首次使用、断网无法自动安装
  Pillow，或系统里找不到中文字体）会直接报错停止，不会静默产出不带角标、或角标文字是方块的成片。
  按提示联网或安装中文字体后重试，也可以在设置里关闭角标。
  角标文案（最多 40 字，默认「内容由AI生成·纯属虚构·请勿代入现实」）和字号（10–24，默认 12）在
  「设置 → 内容模型」里修改。
- 成片先写成同目录下的隐藏临时文件，**全部集都编码成功后才统一改成正式文件名**：中途失败、被停止或崩溃时，
  目录里不会出现截断的成片，上一次的正式成片也保持不动。重新分集后集数变少时（例如 12 集变 10 集），
  上一次多出来的 `第11集.mp4`、`第12集.mp4` 会被自动删除，并写在完成说明里；只删名字是 `第NN集.mp4`
  的文件，你自己放进去的其他文件不会动。
- 停止转码只停转码（含它的材料线程），不影响码率修复。停止时连同 ffmpeg 拉起的子进程一并终止。
- 编码失败（不是你点的停止）时材料线程会立刻停下，不再发起新的 AI 调用；已经生成好的剧名、简介、海报
  保留在输出目录，下次处理直接复用，不会重复付费。
- 单条 ffmpeg 命令的超时按这一集的时长计算（深度处理约为时长的 8 倍，最少 10 分钟、最多 4 小时），
  长集不会再被固定的 10 分钟超时误杀。
- 深度处理还会**并行启动材料线程**：按「设置 → 目录与引擎 → 内容模型」里的抽样集数，用
  ASR 识别对白、OCR 识别画面文字，再让配置的 LLM 生成剧名/简介，并生成海报与
  4 张过程图。材料失败只记警告，不会回滚已经完成的成片编码。
- 材料按剧保存（键是剧目目录），来源顺序固定：剧名 本剧已保存 → AI；
  简介 素材目录里文件名含「简介 / intro / synopsis」的 txt、md → 本剧已保存 → AI
  （素材目录放了简介文件就一定用它）；
  海报 本剧输出目录已有 → AI 生图 → 素材目录封面。已有就不再调模型，来源写进 AI 制作证明。
- AI 关闭时剧名可以手填，离开输入框（或按回车）即保存到当前这部剧名下。
  任何长任务（扫描、探测、深度处理、重做海报等）进行中，三个 AI 开关和剧名输入框都会锁定，结束后恢复。
- 想重新生成剧名和简介，在转码页剧名输入框旁点「清除已保存」，下次深度处理会按上面的顺序重新取值
  （AI 开着且已配置 LLM 时才会重新生成）。
- **海报不会在处理中自动重做**：输出目录已有海报时一律沿用。清单会记下这张海报当初是按哪个剧名和简介
  生成的；如果这次的剧名或简介和它不同，而那张海报是 AI 生成的，结果区会提示「海报仍是旧文案」。
  海报 AI 开着且配置了生图接口时，会出现「按新文案重做海报」按钮，点了才会调用生图接口（产生费用），
  并同步更新 AI 制作证明。没点就不会消失：之后每次深度处理都会再提示，直到重做，或文案改回原样。
  素材封面复制来的海报不随文案变化，不会提示。深度处理进行中不能重做海报，会提示等处理结束。
- **深度处理一开跑就会作废上一轮的 AI 制作证明**：删除 `AI制作证明.png` / `.txt`，清空清单里的成片清单。
  材料流水线开着时，旧过程图也一并删除、计数清零（本轮会重做）；关着时过程图原样保留。
  原因是成片、海报、简介随后会被逐步替换，旧证明不可能再与目录内容对应。
  宁可暂时没有证明，也不留一张写错的。只有本轮完整成功时才生成新证明。
- 中途停止时：
  - 输出目录是本次新建的：整个目录删除。
  - 输出目录原本就存在：本次写出的成片临时文件删除，上一轮的正式成片保留；提示里会写明上一轮证明已作废，
    完整重跑一次深度处理才会生成新证明。
- 编码失败（不是你点的停止）时：成片没有发布，上一轮的正式成片保留；已生成的剧名、简介、海报也保留，
  下次直接复用；提示里同样会写明上一轮证明已作废。
- 深度处理成功但没有生成新证明时（材料流水线关着、材料线程失败或证明渲染失败），完成说明末尾会提示
  「上一轮 AI 制作证明已作废，本轮未生成新证明」。
- 清单里剧名、简介、海报依据保留，下次的过期判断与「按新文案重做海报」照常可用。证明作废后重做海报会重新
  出证明，但成片清单写「未记录（上次深度处理未完成）」（过程图已被清掉时写「未生成」），结果里会提示完整跑一次深度处理以补全。
- 去重配方存证（`去重配方.json`）只在成片全部发布后才写入，停止或失败时不会留下与成片对不上的本轮配方；
  成功后写入失败时，上一轮的存证也会删除，完成说明写明「配方存证写入失败」；本轮关了去重时，上一轮的存证同样删除。
- AI 生成的剧名超过 15 字（或简介超长）时只作废超长的那一项，另一项照常使用，原因写在结果里；
  不会因为剧名多一个字把合格的简介也扔掉、下次再付一次费。
- 已知限制：沿用以前 AI 生成的剧名或简介时，来源只写「沿用」，不再标注当初是 AI 生成的
  （沿用的海报会写明「原为 AI 生成…」）。AI 制作证明会把这类项写成「来源未记录，请制作方确认」。
- **AI 制作证明**（`AI制作证明.png`，图片生成失败时改出 `AI制作证明.txt`，目录里只保留一份）
  在**成片全部编码完成后**生成，内容包括：
  - 处理方式：按本次实际开关列出，包括重组、微帧、编码器、去重配方种子、AI 角标是否烧录；
    开启去重配方时，还会如实写明成片元数据被改写的全部字段（comment / copyright / make / software / creation_time）。
  - 剧名、简介、海报、过程图各自的来源；AI 声明按实际来源逐项写出，只有含 AI 生成内容时页眉才显示「由人工智能辅助制作」。
  - 成片清单与原始素材的文件名、大小、SHA-256：图上各列前 10 行，完整列表在 `material-manifest.json` 的 `proofPayload` 里。
  - 底部留空的「制作方 / 签署 / 日期」，由制作方手写签署。工具不会自动生成签名或公章。
  - 日期按北京时间，取**生成证明的那一刻**（深度处理跨过午夜也不会早一天）。编码失败或中途停止时不生成新证明；
    上一轮的证明在开跑时已作废（见上文）。成片全部编码完成后，即使这时点了停止，成片指纹也照常计算，
    证明不会把已经存在的成片写成「未记录」。
  - 证明图、AI 合规角标、过程图都需要系统中文字体（Windows 用微软雅黑 / 黑体 / 宋体，macOS 用苹方 / 黑体 /
    冬青黑体）。一个都找不到时不会出图：证明改出文本版 `AI制作证明.txt` 并写明原因，过程图记一条警告，
    角标让深度处理在编码前停下。以前会画出一排看不清的方块却显示「已生成」。
- 推荐本机安装 whisper.cpp（显式填写模型文件）与 Tesseract（含 `chi_sim` 语言包）；
  应用不会自动下载大模型，未配置时材料线程会跳过内容提取并在结果里说明原因。
- 输出位置：「设置 → 生成设置」里的**深度处理输出根目录**优先，其次是「默认输出目录」，
  两者都按「该目录 / 剧名 / 深度处理」落盘，多部剧各占一个子目录；都没设才写到「剧目目录/深度处理」。
- 写到输出根目录下的输出目录里有一个归属标记文件 `.dossier-owner.json`，记录它属于哪部剧
  （macOS / Linux 上点开头的文件默认隐藏，Windows 上可见；请不要随手删除）
  （写在剧目目录里面的输出目录不需要标记，也不检查）。不同素材库里有**同名**剧、落到同一个输出目录时，
  后一部会在编码前报错（不会覆盖前一部的成片和海报），请换一个输出根目录或给其中一部剧的目录改名。
  - 标记记录的剧目目录已经不存在（剧目移走或删除）时，由当前剧自动重新认领，日志里会记一行。
    注意：剧目所在的移动硬盘或网络盘暂时没挂载时，也会被当作「已不存在」。
  - 原位置还留着同名目录、但确实是同一部剧搬了家时，删除输出目录里的 `.dossier-owner.json` 后重试。
  - 升级前已存在、没有标记的目录由下一次写入它的剧认领。
- **输出目录不允许等于素材目录**：那种情况会覆盖原素材，界面会在输入框下直接标红拦下，
  后端在真正执行前也会再拦一次。全剧重编码，请预留时间。

### 8.4 报审包差异对比

读两份报审包的 `manifest.json`，列出改稿前后的**新增 / 移除 / 修改**文件，并给出两份报审包的
生成时间对照。它只读清单，不读素材内容，也不改动任何文件。

### 8.5 平台材料要求（示例档案）

- 内置档案是**学习示例**，不是任何平台的官方规范。
- 「对照当前剧目」会逐集对照时长、画幅、码率、编码与必需材料，输出「N 项阻断 / N 项警告」，
  或「无阻断项」。绿色=无阻断、黄色=有警告、红色=有阻断。探测失败的分集每集记一项阻断，原因写在下方说明里。

### 8.6 剪映草稿

- 「导出草稿」：把分集顺序与时长写成剪映草稿目录（留空写到剧目目录），结束后回填实际目录。
  有任何一集探测失败就不导出，并列出失败的文件与原因（避免草稿缺集）。生成挂载文案同样如此。
- 「读回草稿」：选择草稿目录，列出片段顺序、时间线起点与时长，用来和素材核对。
- 剪映草稿格式随版本变化，这只是**交接与核对**用途。

### 8.7 字幕 / 角标擦除（实验功能）

- 只处理**自有素材**的硬字幕与角标；本功能不提供任何绕过版权保护或去除他人作品标识的能力。
- 使用顺序：选输入视频 → 选输出视频 → 填区域（`x,y,w,h`，多个用分号分隔）→
  （可选）检测后端/修复后端与高级参数 → 「预览命令」看将要执行的命令 →
  「执行擦除」。
- **输入与输出不能是同一个文件**：界面会就地拦下，后端在执行前也会再拦一次，避免边读边写毁掉源素材。
- 执行期间进度条是**确定进度**：分「定位字幕区域」「逐片段修复画面」两段，显示到第几段与已完成多少帧。
- 结束后回显结论与退出码（`0` 通过 / `3` 需人工抽查 / `2` 校验失败），以及残留峰值、
  结构相似度最低值和处理日志路径。
- 「检测工具状态」用于确认擦除工具是否可用（缺少模型 worker 时会说明）。由 Desktop build 工作流
  （desktop.yml）打出的安装包内置了擦除工具，支持 `fixed` + `column` 基线；Build Windows 工作流
  （build-windows.yml）打出的安装包暂未内置，需要自行指定擦除工具路径。`worker` 后端需要另行配置
  Python 与模型权重。
- 输出视频所在目录不存在时，执行擦除会自动创建。

## 9. 模块四：设置

### 检查规则与路径

- 可改：最少集数、单集时长下限/上限（秒）、码率上限（Mbps）、是否对横屏分集给警告。
- 可改：默认输出目录（`ffprobe` 路径不在这里，见下一节「本机环境」）。
  它是**产物的根目录**：留空时产物写在各自剧目目录内；填了则按「该目录 / 剧名 / 产物名」落盘，
  多部剧各占一个子目录、不会互相顶掉。生成报审包、智能微调/分集重组都读这个值，
  各页自己的「输出目录」输入框只是**本次运行**的临时覆盖。
- **保存后才生效**：探测与生成都读「已保存的设置」；改了没保存时，标题右侧会显示
  `有改动未保存` 徽标。表单里的临时改动不会偷偷生效。
- 「恢复默认」只回填表单为内置默认值，仍然要点「保存设置」才生效。
- 「生成报审包」页里的同名输入是**本次运行覆盖**，不改变设置。
- 素材根目录不在这一页填：扫描成功后应用会自动记住，下次启动时「剧目库」的目录框会直接回填。
- 设置只写入本机配置文件，页面底部会显示它的**实际路径**（应用配置目录下的 `settings.json`）。
- 设置文件损坏（解析失败）时，启动会提示并暂用默认设置。这期间所有**顺带的保存**都会被拒绝、
  不覆盖原文件——包括扫描剧目时记住目录、拨动 AI 开关、开始深度处理前的保存、剧名与简介的自动写入。
  只有在「设置」页点「保存设置」才会恢复：旧文件先备份为 `settings.json.broken-<时间>`，
  再写入新设置，备份位置会显示在保存成功的提示里（按剧保存的剧名与简介此时读不到，需要时可从备份里找回）。
  文件读不出来（权限不足或被其他程序占用）时，保存会直接报错，不覆盖。
- 一键配置写入的 Python 路径由应用自己维护，在「设置」页保存时会原样保留。

### 本机环境

- 逐项列出 `ffmpeg` / `ffprobe` / `python` 的「已找到 / 未找到」与版本说明。
- **一键配置运行环境**：自动下载安装 `ffmpeg` / `ffprobe`（约 25 MB，需要联网），完成后把路径写入设置
  并重新检测；下载期间按钮会保持禁用，网络慢时可能要等几分钟。**这个按钮只在 macOS 上出现**；
  Windows / Linux 上同一位置显示的是手动安装指引（`winget install Gyan.FFmpeg` /
  `sudo apt install ffmpeg`），装好后再用下面的「ffprobe 路径」指定位置。
- **重新检测**：立刻再跑一遍环境探测。
- **ffprobe 路径（高级）**：手动指定可执行文件位置；留空则由应用按「设置里的路径 → 安装目录 → 系统
  `PATH`」自动查找。改完保存设置会自动重新检测。

### 内容模型（ASR / OCR）

- 深度处理的材料线程依赖两项本机能力：**ASR** 把对白转成字幕，**OCR** 识别画面底部文字。
- ASR 支持 `openai-whisper` CLI 与 `whisper.cpp` CLI。whisper.cpp 必须填**模型文件路径**
  （如 `ggml-large-v3-turbo.bin`）；openai-whisper 填模型名（如 `small`）。
- OCR 使用 Tesseract，必须安装 `chi_sim` 中文语言包；检测会执行 `--list-langs` 核对。
- 「剧情抽样集数」默认 4，最多 16。抽样越多理解越完整，但 ASR/OCR/模型耗时也越长。
- 「深度处理时自动生成材料」默认开启；关闭后深度处理只做重组 + 微帧（去重配方与角标按各自开关），
  不调用 ASR/OCR/LLM/生图，也不生成过程图与 AI 制作证明。
- 材料证据（音频、SRT、OCR 结果、`content.json`）落在输出目录的 `.material-content/`，
  汇总结果在 `material-manifest.json`；海报与过程图直接落在输出目录。

### 关于

显示版本号，并说明所有数据只保存在本机、不做账号与云端同步。

### 软件升级

- 软件启动约 30 秒后会联网检查一次新版本，之后每 6 小时检查一次；也可以在「设置 → 软件」点「检查更新」。
- 发现新版本时，窗口顶部出现提示条，**只提示、不下载**。点「稍后」后，同一版本不再自动提示，手动检查仍会显示。
- 点「立即升级」才会弹出升级窗口并开始下载。下载完成后先校验安装包签名，校验不通过不会安装；
  校验通过后软件自动关闭、安装并重新打开。
- 有转码、擦除、生成报审包、安装运行环境、重做海报等任务在运行时不会安装，会提示等任务结束。
  如果是下载完才发现有任务，安装包会先留着，任务结束后点「重试」直接安装，不用重新下载。
- 授权过期或被锁定时也可以升级。
- 从没有升级功能的旧版本过来，需要手动下载安装一次新版本，之后才能在软件内升级。
- 网络访问 GitHub 不稳定时，自动检查会静默失败（写入运行日志），不影响使用。

## 10. 常见问题与排错

| 现象 | 原因与处理 |
| --- | --- |
| 顶部横幅提示「运行环境未就绪」 | macOS：点横幅上的「一键配置运行环境」自动下载安装（约 25 MB，需要联网）。Windows / Linux：按横幅给出的命令手动安装 FFmpeg（含 `ffprobe`）并确保在 `PATH` 中 |
| 右上角提示「缺少 ffmpeg / ffprobe」 | 点标签或顶部横幅；或在「设置 → 本机环境」里指定 `ffprobe` 路径后保存 |
| 一键配置后仍提示未就绪 | 应用装完会自动重测；若仍缺，检查是否杀软拦截下载，或手动在「设置 → 本机环境」填 `ffprobe` 路径并保存 |
| 找不到「一键配置运行环境」按钮 | 这是刻意隐藏的：该功能只有 macOS 有可用下载源，其他平台请按横幅/设置页给出的命令手动安装 |
| 「探测并检查」失败并提到 ffprobe/启动/PATH | 同上；错误信息里会点名本机缺的是哪个工具 |
| 「请先选择剧集素材根目录」 | 先填/选根目录再点扫描 |
| 提示「报审包目录已存在」 | 换一个输出目录，或先把旧报审包移走/改名（不会覆盖已有材料） |
| 「输出目录不能是素材目录」 | 转码输出不能写回素材目录；清空让应用写到剧目目录下的子目录，或另选目录 |
| 「输出视频不能与输入视频相同」 | 擦除的输入输出必须不同，改输出文件名 |
| 改名按钮是灰的 | 需要先「预览改名计划」，且已有 `待改名` 项、当前没有别的任务在跑 |
| 提示「找不到可显示中文的字体」 | 系统缺中文字体：Windows 确认 `C:/Windows/Fonts` 里有微软雅黑（msyh）或黑体（simhei）；macOS 在「字体册」里确认苹方或黑体可用。装好后重新深度处理 |
| 提示「已经有任务在进行」 | 上一个耗时操作还没结束，等进度条走完再点 |
| 某个按钮点了没反应 | 长任务开始后所有耗时按钮会统一置灰，这是防止重复执行，不是卡住 |
| 检查结果里有「规格读取失败」 | 该集探测出错，报审包与转码都会拒绝；看分集表那一行的原因，修复或移走该文件 |
| 码率修复后仍提示低于安全线 | 修复结果已变化，需要重新「检测码率」；个别失败项会在结果里列出原因 |
| 「探测不到码率」 | 该文件本身没有可用码率信息，需要人工确认 |

如果应用无响应：先等进度条结束（重编码与擦除可能数分钟）；确认无任务后再操作。

## 11. 已知限制

- 界面**不做**素材的剪切/合成，转码与重编码只做规范化与分集重组；时长/内容层面的修改请回剪辑软件。
- 「平台材料要求」是内置示例档案，不是官方规范；请替换为平台方最新要求后再使用。
- 擦除是实验能力：小掩码（角标/窄字幕条）精度最高，大面积或复杂背景需要人工抽查；
  缺少模型 worker 时部分后端不可用。
- 擦除进度的粒度是**每 30 帧一条**（管线按片段上报），不是逐帧；进度条会成段往前走。
  另外阶段内还没拿到总量时（素材未写 `nb_frames` 等）会先按不确定进度显示，拿到帧数后自动切换。
- 剪映草稿格式随剪映版本变化，读回功能可能受版本影响。
- 报审包生成不做增量更新：目标目录已存在就拒绝，需要你显式换目录。
- 检查规则可配置，但**规则再严也代替不了人工复核**：`材料可用` 只表示无失败项。

## 12. 隐私与合规边界

- 应用只在两种情况下访问网络：① 启动本机 `ffprobe` / `ffmpeg` 等外部进程（不联网）；② 你**主动点击**「一键配置运行环境」时下载官方 ffmpeg 压缩包。素材与报告始终不上传、不含云端同步。
- 设置里填写的公司、联系方式等只写入本机报审包与本地配置。
- 剧备只整理**使用者提供的真实材料**，固定包含内容权属声明模板，但**不伪造**签名、印章或时间戳；
  `manifest.json` 是本地完整性清单，不是官方审核回执。
- 擦除功能仅限自有素材；不提供 DRM 绕过，也不处理他人作品的版权标识。
- 本项目定位为技术学习与交流的示例，文中的报审格式、平台要求与发布流程都不构成合规或法律意见。

## 附录 A：报审包目录结构

```text
报审包/
├── 01_剧集信息/
│   ├── 剧名.txt
│   └── 简介.txt
├── 02_封面海报/
│   └── 封面.jpg
├── 03_分集清单/
│   └── 分集清单.csv
├── 04_成本配置表/
│   └── 成本配置表.md
├── 05_权属声明/
│   └── 内容权属声明.txt
├── 06_分集视频/        # 仅在勾选「复制分集视频进报审包」时生成
│   └── 第01集.mp4
└── manifest.json
```

- 包内文件统一命名，**扩展名跟原文件**：简介 `简介.txt` / `简介.md`，封面 `封面.jpg` / `封面.png` 等，
  分集 `第NN集.<原扩展名>`（NN 至少两位，最大集号三位数时为三位）。解析不出集号的分集保留原文件名。
- 集号重复（或撞上已有名字）时，按（有集号在前、集号、完整路径）的固定顺序给后来者加 `-2`、`-3`：`第03集.mp4`、
  `第03集-2.mp4`。比较不区分大小写。每个分集都会进包，不会互相覆盖。
- `分集清单.csv` 带 BOM（Excel 直接打开不乱码），以 `=`、`+`、`-`、`@` 开头的单元格加英文单引号防公式注入；
  末尾「包内文件名」列对应 `06_分集视频/` 里的名字（没勾选复制分集时为空），「文件名」列仍是原文件名。
- 成本配置表的金额与占比最多两位小数；公司名、联系方式里的 `|` 会转义，不会破坏表格。投资额必须不小于 0、
  占比必须在 0–100 之间，否则不生成。
- 用「报审包差异对比」比较本版本与旧版本生成的包时，改名的文件会显示为一批新增与移除，属正常现象。
`manifest.json` 记录 `schema`、剧名、生成时间、是否 AI 辅助、是否复制分集，以及包内每个文件的
`path` / `sizeBytes` / `sha256`（不含 `manifest.json` 自身）。完整字段见
[`MATERIAL_SPEC.md`](MATERIAL_SPEC.md)。

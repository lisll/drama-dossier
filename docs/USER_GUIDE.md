## 1. 这是什么

剧备是一个**本地优先**的桌面应用：素材、检查报告和生成出来的报审包都留在你自己的电脑上，
不上传、也不做云端同步——**只有「服务端处理」这一页是你主动把视频传上去的**（见 9）。

它帮你把这几件重复劳动自动化：

1. 按约定扫描本机的剧集素材目录，认出「一部剧 = 一个子目录」；
2. 调用本机 `ffprobe` 读取每一集的时长、分辨率、编码、帧率、码率；
3. 按可解释的规则给出检查结论（哪些缺失、哪些需要人工确认）；
4. 生成编号清晰的报审包目录 + 由服务端签名、桌面端验签后组装的完整性清单 `manifest.json`；
5. 按服务端签发的配方，给一部剧生成一套通用处理版本（带画质检测，可暂停续跑）；
6. 把一集视频传到服务端处理，跑完再把产物下载回来（不占本机算力，失败会退还预扣的积分）；
7. 附带一个后期工具箱（改名、码率修复、转码、差异对比、草稿交接、字幕/角标擦除）。

**必须联网才能用的功能有三处**（账号登录、兑换和刷新授权、充值积分与查余额本来也要联网）：

- **生成报审包**：要登录账号，并且账号要有**有效使用权**。发出去的内容只有剧目信息、
  成本表单和各文件的**文件名、大小、SHA-256 与探测规格**——分集视频、封面、简介**只发校验值、不上传文件**。
  服务端按这些信息生成文档、给清单签名，文件回到本机后再由桌面端组装成报审包；
- **开始生成处理版本**：同样要登录账号和有效使用权，要向服务端申请一份配方（配方只能用一次；
  预览计划、暂停后续跑都不用联网，续跑用的是本机保存的配方原文）；
- **服务端处理**：整页都要联网。它是唯一会把**视频文件本身**发到服务端的功能——分块上传、跑完下载产物。

生成报审包与申请处理配方这两步都只发文件的校验值和任务描述，**素材文件始终不上传**。

**它不做什么**：不代你填真实信息、不伪造签名/印章/时间戳、不替代平台审核、不绕过任何版权保护。
规则里的阈值与「平台档案」都是**学习示例**，接入真实业务前必须换成平台方最新规范。

## 2. 装好之后先做一次环境自检

剧备自己不含视频工具，需要本机有 **FFmpeg（必须包含 `ffprobe`）**。可以自己装，也可以让应用帮你装。

- 启动后，如果缺少工具，窗口**顶部**会出现一条**运行环境横幅**，上面直接带「一键配置运行环境」按钮：
  点一下会自动下载安装 `ffmpeg` / `ffprobe`（约 25 MB，需要联网），装好后路径自动写入设置并重新检测；
  环境就绪后横幅自动隐藏，不再占版面。**不用等你点了按钮才发现跑不通。**
  - 该按钮**在 macOS 与 Windows 上出现**：macOS 下载 evermeet.cx 的构建（用系统自带的
    `/usr/bin/curl` 与 `/usr/bin/unzip`）；Windows 下载 gyan.dev 的按版本归档包（用系统自带的
    `curl.exe` 与 `tar.exe`，Windows 10 1803 之前的系统没有这两个工具，会直接提示「系统版本太旧，
    请手动安装」）。Linux 上**不会**显示这个按钮，横幅与「设置 → 本机环境」改成给出手动安装命令：
    `sudo apt install ffmpeg` / `sudo dnf install ffmpeg`。
  - 下载完会**先校验 SHA-256 再解压安装**：校验不符时删除下载的文件、不安装、不写设置，并换下一个来源。
    Windows 配了两个来源（gyan.dev 优先，BtbN 次之），全部失败时错误信息里会逐条列出每个来源的失败原因
    和手动安装步骤。这些包都是**第三方构建**（不是 FFmpeg 官方发布物），哈希只能保证「下到的就是你钉住的
    那一版」，不能证明来源可信。
  - Apple 芯片（Apple Silicon）首次使用若提示 CPU 架构不匹配，请先在终端执行
    `softwareupdate --install-rosetta --agree-to-license` 安装 Rosetta 2，再重新点击一键配置。
- 窗口右上角另有一个**常驻环境标签**，随时反映状态：
  - `本机环境就绪`（绿）：可以正常扫描、探测、生成；
  - `缺少 ffmpeg` / `缺少 ffprobe`（红）：还没找到，点一下跳到「设置 → 本机环境」看详情；
  - `环境异常：ffmpeg / ffprobe`（黄）：找到了但不可用（例如路径指向了别的程序），同样点标签查看。
- 「设置 → 本机环境」里除了「一键配置运行环境」，还有「重新检测」，以及一个高级项
  「ffprobe 路径」（例如 `/opt/homebrew/bin/ffprobe`、`C:\ffmpeg\bin\ffprobe.exe`）。
  **留空时**应用按「设置里的路径 → 安装目录 → 系统 `PATH`」的顺序自动查找。

缺 FFmpeg 时仍然能做的事：**扫描剧目**（只读文件名与体积）。会失败的事：**探测并检查**、
生成报审包、码率修复、执行转码、生成处理版本（这一页顶部会直接给出「下载运行环境」入口）。
注意「一键配置运行环境」是应用里**唯一**会主动下载文件的动作，
且只下载官方的 ffmpeg 压缩包。

## 3. 界面总览

界面是一列左侧导航 + 六块工作区，任何时刻只显示一块；此外侧栏底部还有一个常驻的「任务」入口：

| 区域 | 作用 |
| --- | --- |
| 首页 | 欢迎栏、**公告轮播**、新手引导、近 7 天统计、教程 |
| 剧目库 | 选素材根目录 → 扫描 → 点选一部剧 → 探测并检查 |
| 生成报审包 | 填写出品方、投资额等信息并生成报审包 |
| 处理版本 | 声明权属材料、调版本模板，按服务端配方给一部剧生成一套通用处理版本 |
| 服务端处理 | 把一集视频传到服务端跑，跑完下载产物（需联网、按集扣积分） |
| 工具箱 | 改名、码率修复、转码、报审包对比、平台档案、剪映草稿、区域擦除 |
| 设置 | 检查规则阈值、默认路径、本机环境、剪映、关于 |
| 任务（侧栏底部） | 处理版本与区域擦除的任务队列：看进度、暂停、继续、终止 |

### 首页的公告

公告**由服务端下发**（运营在管理后台里写），不再写死在程序里。右上角显示「第几条 / 共几条」，
可以点 `‹` `›` 手动翻，也可以点「暂停」停掉自动轮播。

- **拉不到公告时显示「暂无公告。」**，不会显示过期或来路不明的通知。断网、服务端没起、
  服务端还没升到有公告功能的版本，都会是这一句；
- 公告分两档：普通（`info`）与提醒（`warn`）。提醒类在视觉上更醒目；
- 最多显示 20 条，按运营设定的排序值从小到大排；
- 只有「显示中」且在生效时间窗内的公告会下发，停用或过期的不会显示。

界面上还有这几样东西（大部分在顶部，最后一项在侧栏底部）：

- **版本提示横幅**（顶部，紧挨账号横幅）：分两级。只是有新版本时是黄色提示「有新版本可用」；
  当前版本低于服务端要求的最低版本时变成红色「这个版本已停止支持」，提示你更新后继续使用（见 [14](#14-常见问题与排错)）。
  两种横幅里都带「下载并校验升级包」按钮（管理员没填下载地址时改为提示联系客服）；
- **运行环境横幅**：只在缺少 `ffmpeg` / `ffprobe` 时出现，装好即隐藏。macOS 与 Windows 上带
  「一键配置运行环境」入口，Linux 改为直接给出该平台的手动安装命令；
- **常驻环境标签**（右上角）：随时显示「本机环境就绪」或缺哪个工具，点一下跳到「设置 → 本机环境」；
- **当前剧目**标签：提醒你现在所有操作都作用在哪一部剧上；
- **账号菜单**（点侧栏底部的账号区打开）：第一项是「积分与充值」，后面依次是「兑换卡密」「设备管理」
  「账号设置」「退出登录」。账号区平时只显示邮箱和使用权徽标（如「永久」「到 2026-11-14」）；
  **剩余积分在鼠标悬停的提示与读屏标签里**（读屏标签形如「账号 you@example.com，永久，剩余 120 积分，打开账号菜单」），
  完整余额与流水在「积分与充值」里看（见 [13](#13-积分与充值)）；
- **进度条**：所有耗时操作都会显示。逐集探测能算出总量时是**确定进度**（`正在探测分集 3/12：第03集.mp4`），
  转码与码率修复按「第 3/8 集」这类单元显示确定进度；处理版本在预览计划时逐集核对哈希，同样显示
  「正在核对第 3/12 集」；服务端处理按「已传/总块数」显示上传进度（分母用服务端给的总块数）。
  区域擦除取帧、自动识别、对比预览都是单步操作，批量擦除则交给「任务」队列
  按「第几集」显示确定进度（命令行 `dossier-inpaint` 自己另有逐片段帧级进度，见 `--progress-json`）。
  真的算不出总量时才退回**不确定进度 + 已用秒数**；
- **提示条（Toast）**：失败用红色并统一带「出错了：」前缀，停留时间也更长（9 秒，成功为 4.5 秒）。
  除了颜色还有文字前缀，截图或投屏也能分辨成功与失败。
  路径、权限、运行环境这类**能指出下一步**的错误会直接带一个按钮（「打开设置」/「重新检测」/
  「去设置环境」），点了就跳过去，不用自己翻页找。

**长任务只允许一个**：只要有任务在跑（扫描、探测、生成、改名、码率检测/修复、转码、平台对照、
草稿读写、擦除、预览处理计划），所有耗时按钮都会自动置灰，避免重复点击把同一件事跑两遍。
想再点会提示「已经有任务在进行」。处理版本的「开始生成」只在提交那一刻占用这个开关：
提交完就交给「任务」队列在后台逐集跑，你可以照常去别的页面操作。

## 4. 五分钟上手

1. 打开应用 → 左侧「剧目库」。首次进入时中间会有一份**三步引导**（选择目录 → 扫描剧目 →
   点选剧目并探测），每完成一步前面的圆圈会打勾，也可以直接点引导里的按钮走完，不必自己找入口。
2. 在「素材根目录」里输入或点「选择」挑一个目录（里面每个子目录 = 一部剧）。
   扫描成功后这个路径会**自动记住**，下次启动直接回填。
3. 点「扫描剧目」，左侧会列出找到的剧目与集数、总体积。
4. 点选一部剧 → 点右上角「探测并检查」，等待进度条走完。
5. 看「检查结果」（通过 / 需确认 / 不通过）和「分集」表，按提示补齐缺失材料。
6. 切到「生成报审包」，填出品方等信息 → 点「生成材料包」（这一步需要联网，账号要有有效使用权，
   并且积分够扣——按一集 5 积分算，余额不够会提示「积分不足，请先充值」，充值入口在账号菜单的「积分与充值」）。
7. 生成完可以点结果里的「打开目录」直接跳到报审包，或「复制路径」发给同事。
   注意包里的两份 PDF 是**占位章、未签署**，正式报审前要换成盖章版本。

## 5. 素材怎么准备

推荐的目录结构（根目录下每个子目录是一部剧）：

```text
素材根目录/
└── 示例短剧/
    ├── 第01集.mp4
    ├── 第02集.mp4
    ├── 封面.jpg
    └── 简介.txt
```

- 视频扩展名：`mp4`、`mov`、`mkv`、`flv`、`ts`、`m4v`、`webm`；
  图片：`jpg`、`jpeg`、`png`、`webp`；文本：`txt`、`md`。
- 剧目目录内部的**一层子目录**也会被扫描。
- 集号解析优先级：① `第12集` / `第12话` / `第12回` → ② 词边界的 `E12` / `e03` → ③ 主干里的独立数字（`show_12`）。
  解析不出集号的文件会被列入「无法解析」并保持不动（不会乱改名）。
- 封面建议 `封面.jpg`，简介建议 `简介.txt`，不少于 30 字，写清题材、主要人物、受众定位。

> 小贴士：文件名不统一时，先去**工具箱 → 批量改名**把它统一成「剧名 - 第NN集」，
> 再做探测与生成——集号解析依赖文件名。

## 6. 模块一：剧目库

### 扫描剧目

- 输入/选择根目录 → 「扫描剧目」。找不到子目录时会显示「未找到剧目子目录。」。
- 左侧剧目条目显示：剧名、集数、素材总体积。
- **切换剧目或重新扫描会作废工具箱里上一部剧的计划与结论**，防止拿旧计划点执行。

### 探测并检查

点「探测并检查」后逐集读取规格，结果分两块：

- **检查结果**：每条给出「项目 + 状态 + 说明」。状态含义：
  `通过` / `需确认`（警告，需要人工判断）/ `不通过`（缺失等失败项）/ `尚未探测`。
  右上角徽标是总览：`材料可用`（无失败项）或 `有缺失项`。
- **分集**表：集号、文件名、时长、`宽×高`、状态。探测失败的那一行直接显示失败原因。

`材料可用` 只代表**没有失败项**，警告项仍然要人工确认。

## 7. 模块二：生成报审包

这一页**需要联网**，并且账号要有**有效使用权**：执行前会先联网刷新一次授权，断网时提示
「这一步需要联网：连不上服务端，请联网后重试」；没有使用权时提示「这个账号还没有使用权，请先兑换卡密」。
发往服务端的只有：剧目信息（剧名、是否 AI 辅助）、成本表单、以及每一集的
**文件名、大小、SHA-256、探测规格**和封面 / 简介的同一组信息——**分集视频、封面、简介都不上传**。

上半部分是「本次运行覆盖」，只影响这一次；长期默认值在「设置」里。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 输出目录（本次覆盖） | 否 | 留空 = 按「设置 → 默认输出目录 / 剧名 / 报审包」落盘，设置也为空时才写到「剧目目录/报审包」。填了就生成到你指定的目录 |
| 出品 / 公司 | 否 | 写进报审包的成本表与权属声明；请填**真实**信息 |
| 投资总额（万元） | 否 | 必须是不小于 0 的数字（上限 1e9），格式错误会在输入框下就地标红 |
| 演员成本占比（%） | 否 | 必须在 0–100 之间 |
| 联系方式 | 否 | 随成本表单发给服务端，用于生成成本配置表；服务端不保存文档内容，审计日志里也不记原文 |
| 复制分集视频进报审包 | 否 | 勾选后会额外生成 `06_分集视频/`（最耗时的一步，进度条会说明） |
| 使用了 AI 辅助生成 | 否 | 如实勾选，会记进 `manifest.json` 的 `aiGenerated` |

这一页**不再单填 ffprobe 路径**：读取规格用的 `ffprobe` 统一取「设置 → 本机环境」里的配置
（留空则自动查找）。

点「生成材料包」后依次做三件事：**先重新探测一遍**（避免用过期规格）→ 逐集算 SHA-256（进度条会说明）
→ 把上面那组信息发给服务端。服务端生成文本文件、把成本配置表和内容权属声明渲染成 PDF 并盖章、
给清单签名，发回本机后桌面端**先验签**，再把分集、封面、简介放进去并**逐个重算哈希比对**，
全部对得上才写出报审包；中途失败不会留下半个目录。最后结果里给出位置、文件数与总大小，
并提供「打开目录 / 复制路径」。

几点须知：

- **默认盖的是占位章**：成本配置表与内容权属声明的 PDF 上是灰色虚线框 +
  「样章 · 未签署 · 无法律效力」+ 整页「草稿 · 未签署」斜向水印，文件名带 `_未签署` 后缀。
  它**不是**盖章文件，也**不具备法律效力**。正式报审前必须换成盖章版本。
- **已经有盖好章的扫描件时，可以让它代替占位章**：展开「用已盖章的扫描件代替占位章」，
  两份文档（成本配置表、内容权属声明）可以各上传一份扫描件。**可以只给其中一份**，
  给了的那份用扫描件，没给的仍然盖占位章。支持 PNG / JPEG / PDF，单份不超过 5 MB。
  扫描件的页数必须和原文档一致，否则会被拒绝。
- **结果里逐份写明用了哪种章**：给出「扫描件签章」或「占位章 · 未签署 · 无法律效力」两类结论，
  不会笼统写成「已签章」。只要还有一份是占位章，结果区会另外提示「还有 N 份是占位章」。
- **提交之后改动或调换了分集，会被拒绝并要求重新生成。** 服务端记的是提交那一刻的文件名、大小和
  SHA-256：文件被移走或改名会提示「找不到本机文件 … 请重新生成」；内容变了或两集对调了会提示
  「… 在提交后被改动或调换过（内容和提交时不一致），请重新生成」。这两种情况都不会写出半个包。
- 目标目录**已存在**时会直接拒绝，提示「报审包目录已存在」，不会覆盖已有材料。
  这时结果区会直接给出旧包位置，可以点「打开目录」先确认；提示条上还有「换个输出目录」按钮，
  点一下就能重新挑目录再生成（旧目录始终不会被改动）。
  目录已存在会**在本机先挡下来**，不占用一次服务端生成次数。
- 生成失败时结果区用红色展示，不会与成功色混淆。
- 报审包结构与 `manifest.json` 字段见[附录 A](#附录-a报审包目录结构)与 [`MATERIAL_SPEC.md`](MATERIAL_SPEC.md)。

**扣费说明**

- 生成报审包要花积分，**按集算，一集 5 积分**。点「生成材料包」后、真正开工前会先弹一次确认框
  （这部剧识别到集数时才弹），写明「《剧名》共 N 集，按每集 5 积分计算，将消耗 X 积分」，点「生成」才继续。
  这个数字是界面按当前价目算的预估，**准确数额以服务端扣的为准**；
- 服务端是**先预扣再渲染**：余额不够时不开始渲染，直接提示「积分不足，请先充值」；
- **生成失败会把预扣的积分自动退还**：因为报审包由服务端生成，它知道这一步到底成没成。
  退款在流水里是一条正的「退还」，原来的预扣标为「已退还」，两笔都留着痕迹；
- 目标目录已存在这类**在本机就挡下来**的情况不占用服务端生成次数，也不扣积分；
- 余额与流水在账号菜单的「积分与充值」里看（见 [13](#13-积分与充值)）。

## 8. 模块三：处理版本

这一页给**一部剧**生成**一套**通用处理版本（只做一套，不区分平台）：输出目录是
`<产物根>/<剧名>/处理版本/`，「产物根」取「设置 → 默认输出目录」，没设时写在剧目目录下。
目录里有各集视频（和源文件同名，后缀统一换成配方给出的容器，现在是 `.mp4`）、`封面.jpg` 和 `版本说明.json`。

> 配方由服务端签发、**只能用一次**，所以「开始生成」这一步需要联网，账号要有有效使用权，
> 并且积分要够（按集扣，见 [8.6](#86-积分怎么扣)）。
> 选档位、改模板、预览计划都只在本机算，不联网、不扣次数。

### 8.1 操作顺序

1. **选剧**：先在「剧目库」扫描并点选一部剧，本页顶部会显示当前剧目；
2. **声明权属材料**（见 8.2）；
3. **选强度档**：「轻 / 中 / 重」，档位越重变化越大、画质下限也放得越宽；
4. **填模板并保存**（见 8.3）：表单有改动时标题右侧会亮「有改动未保存」，
   预览和生成**只认已保存的模板**，所以要先点「保存模板」（不想改了可以点「放弃改动」）；
5. **预览计划**：逐集列出时长、原分辨率、有没有字幕，并列出每集要做的处理和「还不能开始生成」的原因；
   **「开始生成」只有在预览通过之后才能点**，改了档位或模板要重新预览；
6. **开始生成**：二次确认后向服务端申请一份处理配方并立即用掉（这一步按集扣积分，见 8.6），任务进入队列；
7. **去「任务」看进度**（见 12）：侧栏底部的「任务」里能暂停、继续、终止，也能打开产物目录。

### 8.2 权属材料

- 每部剧声明一次：点「选择文件并声明」，选一份**版权登记证书或授权书扫描件**（支持 `pdf` / `jpg` / `jpeg` / `png`）。
- 程序**只记下文件路径和校验值，不核验真伪**。它的作用是留一份记录、划清责任：
  声明会记进本机的处理台账，申请配方时也会把材料哈希绑进任务。
- 文件**被改动或移走**之后，本页会变成「需要重新声明」，点「重新选择并声明」即可；
  没重新声明就不能生成。

### 8.3 版本模板能调什么

模板保存在剧目目录的 `版本模板.json`，逐部剧一份，换剧会换成那一部剧的模板。

| 分组 | 可调的内容 |
| --- | --- |
| 片头 / 片尾 / 封面 | 片头视频、片尾视频（都可以不填，没有音轨的会补静音）；封面取第 1 集第几秒（默认 1 秒）；封面文字（可不填，不填就不叠字） |
| 字幕与调色 | 字幕文件夹（按集名对应 `.srt`，可不填，不填就不烧字幕）、字幕字号（像素，默认 56）、字幕离底边（像素，可不填）、调色预设（原色 / 暖色 / 冷色 / 高对比 / 低饱和五档） |
| 剧名水印与 AI 标识 | 水印文字（不填就不放）、水印位置（四角之一，默认右上角）、水印透明度（0–1，默认 0.5）；「本剧视频含 AI 生成内容」勾选框与 AI 生成合成服务提供者名称 |
| 节奏与背景音乐 | 「先按场景切点重新分集」与重新分成几集（留空 = 和原来一样多）；背景音乐文件、音乐音量（0–1，默认 0.5）、「我有这段音乐的使用授权」勾选框 |

模板决定的是**看得见的内容和节奏安排**（片头片尾、封面、字幕、调色、水印、AI 标识、重新分集、背景音乐）；
输出规格和细微处理参数不在模板里（见 8.4）。

几条硬性限制（界面会直接拦下或标红）：

- 用了背景音乐就**必须**勾上「我有这段音乐的使用授权」，否则保存不了；
- 勾了 AI 标识时，剧名水印**不能**放在右下角（那里留给 AI 标识）；
- AI 生成合成服务提供者只能用字母、数字和常见英文符号（不能有空格、中文、引号、反斜杠）；
- 「重新分集」和「烧字幕」不能同时开：重新分集后原字幕的时间对不上；
- 重新分集的集数最多是原集数的 10 倍。

### 8.4 哪些东西改不了

- **输出规格**由服务端配方给出，页面上只是显示：1080×1920 竖屏、30 帧、H.264 + AAC、
  视频码率不超过 5000 kbps、单集时长上限 15 分钟（比例不一致时等比缩放加黑边）；
- **细微处理参数**（颗粒、轻微放大裁边、亮度饱和度色相微调、变速变调、首尾裁几帧）的数值同样来自配方，
  你只能选档位，不能逐项调；
- **画质下限**也来自配方。

### 8.5 需要联网的地方

- 「预览计划」只在本机核对，不联网、不扣次数。
- 「开始生成」要向服务端申请一份处理配方，并**立即用掉**：配方只能用一次，
  换档位、改模板就得删掉这次的版本目录重新申请。万一配方用掉之后任务没能排队（极少见：磁盘写不进去），
  会明确提示「配方已经用掉，请稍后重新申请」，这次不会生成任何文件。
- 任务中途暂停或终止**不用重新申请**：点「继续」会用本机保存的配方原文接着做。失败的任务也能「继续」；
  但如果失败原因是文件层面的（源文件在申请后被改动、背景音乐换了、配方校验不过），继续会再失败，
  那就得恢复文件，或者删掉这次的版本目录整个重做——**重做要重新申请配方**（配方一次性，服务端也有限流）。
- **续跑不用联网**：用本机保存的配方原文重新校验，参数和种子不变，产出的文件和第一次完全相同。
- 配方绑定的是**申请那一刻的那批文件**：申请时按内容算过哈希，每集开工前还会重算一次，
  分集被换掉或改过就拒绝处理这一集。

### 8.6 积分怎么扣

- 处理版本**按集扣费，一集 5 积分**（价目由服务端决定）。集数是申请配方时报给服务端的，
  价格在**签发配方时定死**：签发之后价目表被改过也不影响，这次仍按签发时的价扣，不会「签发时说 25、扣钱时扣 30」。
- 点「开始生成」前的确认框会写明「本剧 N 集，按每集 5 积分计算，预计消耗 X 积分（准确数额以服务端签发时为准）」，
  确认后才申请配方。
- **扣费发生在消费配方的那一刻**，也就是开始处理之前，界面上对应的说法是「这笔积分在开始处理前就会扣掉」。
  余额不够时这一步直接失败并提示「积分不足，请先充值」，**什么都不会生成**；充值后可以重新申请。
- **处理失败不退积分。** 这和其他地方不一样，原因很直接：视频只在本机处理、不上传，
  服务端看不到处理结果，无法判断是真失败还是想白用一次。确认框里写明了这一点，请确认材料和档位再开始。
  同理，中途暂停、终止也都不退——「继续」用的是本机保存的配方原文，不再扣费。
- 要换档位或改模板得删掉这次的版本目录重做，**重做会重新申请配方，也就是再扣一次**。
  所以档位和模板最好在预览阶段就定下来（预览只在本机核对，不扣费）。

### 8.7 画质检测

每一集都在同一次编码里分出一路「只做几何处理」（缩放、补边、裁首尾帧、变速）的画面作参考，
和「做完颗粒与调色之后」的画面对比，算出 SSIM 与 PSNR——字幕、水印、AI 标识是有意加的内容，
不算画质损失。低于配方下限的那一集判为**失败、不交付**，这一集的输出文件会被删掉，不会留下半成品；
收尾时只把通过检测的集写进 `版本说明.json`，并在里面记下档位、配方编号与种子、输出规格、
画质下限、每集的画质分数、实际使用的编码器和输出文件的校验值，方便事后复核。

### 8.8 AI 标识

勾了「本剧视频含 AI 生成内容」之后：

- 成片**开头 3 秒**在右下角显示「人工智能生成合成」，之后同一位置常驻「AI生成」；
- 文件元数据里同时写入隐式标识（生成合成服务提供者、内容制作编号）；
- 剧名水印不能放在右下角；
- 画面上要写字（水印、AI 标识、封面文字）就需要**中文字体**：应用会先找系统字体，
  找不到时会挡下生成并提示去「设置 → 本机环境」指定字体文件。

## 9. 模块四：服务端处理

这一页把**一集**视频传到服务端跑，跑完再把产物下载回来。它和「模块三：处理版本」是两条并存的路，
区别见 9.5（「服务端处理与本机处理的区别」）。

> 这一页**必须联网**，账号要有有效使用权，并且积分要够（按集扣，一集 5 积分）。

界面分三步：**上传素材 → 提交处理 → 任务与产物**。

### 9.1 上传素材

1. 先在「剧目库」扫描并点选一部剧，页面顶部会显示当前剧目；
2. 点「开始上传」。程序会先算出**整个文件**的校验值（大文件要几十秒，这段时间没有进度条），
   再向服务端开一个上传会话，然后按服务端给的分片大小（**8 MiB 一块**）逐块上传；
3. 进度区显示「已传/总块数」与百分比。分母用的是**服务端给的总块数**，不用本地估的——
   本地算错会显示「传完了其实没传完」；
4. 全部传完后程序自动「完成上传」：服务端把分片按序拼起来，顺便算一遍整文件校验值，
   和上传前声明的那个比对。对得上才登记成可用素材，对不上会整单作废并让你重新上传。

**断点续传怎么用**：

- 上传中断（断网、关掉客户端、进程崩了）后，**还是点「开始上传」**。只要选的是**同一集**，
  程序会接着用上次那个上传会话：先问服务端「哪些块已经有了」，然后**只补缺的那些块**，
  已经传过的直接跳过，进度里会写明「跳过 N 块已传的」；
- 换了一集就是新的一次上传，不会接着传别的文件；
- 想彻底放弃这次上传，点「放弃上传」：服务端会删掉已经收到的分片，磁盘上不留东西。
  传了一半就不管了也不会永久占地方——服务端跑 `cleanup` 时会清掉超过 **7 天**没动静的上传会话。

### 9.2 提交处理

1. 选「处理方式」（下拉里的配方名，例如「通用处理（不改内容）」「角标擦除」）；
2. 点「提交到服务端处理」。

**扣费规则**：

- **按集计价，一集 5 积分**，价格由服务端给，界面上不自己算；
- 提交时服务端**先预扣**这一单的积分，扣到了才建任务。余额不够会被直接拦下并提示
  「积分不足，请先充值」，**不会建任务**，充值后重新提交即可；
- 同一个提交重复点两次不会扣两次（服务端按幂等键去重）；
- 预扣成功后如果任务**没建起来**（参数错、服务端出问题），这笔预扣会被退回去。

### 9.3 任务状态

提交后下面会出现任务卡片，显示九种状态之一：

| 状态 | 含义 |
| --- | --- |
| 已提交 | 任务记录建好了 |
| 排队中 | 等 Worker 来领 |
| 正在处理 | 服务端在跑 |
| 校验中 | 跑完了，在做产物校验 |
| 等待重试 | 这一轮出错，按退避等下一轮 |
| 正在取消 | 你点了取消，等做到步骤边界时停下 |
| 已取消 | 停下了 |
| 已完成 | 成功了 |
| 失败 | 出错了，卡片上会写原因 |

- 结束状态是「已完成 / 已取消 / 失败」，到了这三态界面就**不再自动刷新**，按钮也会变成「已结束」；
- 没结束时按钮是「取消任务」。取消是**协作式**的：不会强行打断正在跑的 ffmpeg，
  而是在步骤边界退出，避免留下半个文件；
- 想看最新状态随时点「刷新」。

### 9.4 下载产物

- 任务「已完成」之后，产物区会按顺序列出每个输出文件，按钮上写着编号与大小，
  点一下就下载；
- 下载用的是**短时链接**（15 分钟有效）。过期后再点「刷新」重新取一次即可；
- 产物在服务端有保留期，过期会被清理。想要的东西及时下载回来。

### 9.5 服务端处理与本机处理的区别

| | 服务端处理（本页） | 本机处理（模块三：处理版本） |
| --- | --- | --- |
| 视频去哪 | **上传到服务端**，产物也在服务端，要下载回来 | **不出这台电脑**，只把文件的校验值发给服务端 |
| 要不要联网 | 上传、提交、查状态、下载都要联网 | 只有「申请配方」那一步要联网；暂停后续跑不用 |
| 谁在算 | 服务端 Worker | 你自己的电脑（吃满 CPU/GPU） |
| 花不花积分 | 花，**一集 5 积分**，提交时预扣 | 花，**一集 5 积分**，消费配方时一次扣定 |
| 失败退不退 | **退**：任务失败或被取消，预扣的积分会退回来 | **不退**：视频不上传，服务端看不到成败 |
| 产物在哪 | 服务端，用短时链接下载 | 本机 `<产物根>/<剧名>/处理版本/` |
| 一次处理几集 | **一次一集**（见 9.6） | 一次一部剧的所有集 |
| 能调模板吗 | 不能，只选「处理方式」 | 能，片头片尾、字幕、调色、水印、AI 标识等 |

一句话：**本机处理省上传、能调模板；服务端处理不占你的电脑、失败能退积分。**

### 9.6 已知限制（本模块）

- **一次只处理一集**：服务端按集计价，多集上传要排队，这一版先把「传一集 → 处理一集 → 下载」走通；
- **产物下载用短时链接**：过期要重新点「刷新」获取，链接不能转发给别人长期使用；
- **必须联网**：断网时上传、提交、查状态、下载都用不了；已经提交到服务端的任务不受影响，
  联网后回来看结果即可；
- 上传前算整文件校验值那一步没有进度条，大文件会等一会儿。

## 10. 模块五：工具箱

工具箱顶部有一张「该用哪个工具？」引导卡，先按它选工具：

| 你的目标 | 用哪个 |
| --- | --- |
| 只想先看看要改什么 | 视频转码 → **转码建议**（只出建议，不动文件） |
| 只是码率不达标 | **码率修复**（会就地重编码，**替换原文件**） |
| 要改时长、顺序或分集数 | 视频转码 → **执行转码**（输出到新目录） |
| 文件名不统一 | **批量改名**（集号解析依赖文件名） |

工具卡片默认折叠，点标题展开。除改名与码率修复外，其余工具都会**另写新目录**，不动原素材。

### 10.1 批量改名

- 「预览改名计划」：列出每集的当前文件名 → 目标文件名（规则：`剧名 - 第NN集`）与状态
  （`待改名` / `已合规`）；解析不出集号的文件会单列为「无法解析、保持不动」。
- 预览是**必须的第一步**：没有计划，「应用改名」是灰的。
- 目标名冲突或重复时**整体拒绝**，不会改到一半。
- 应用成功后旧计划立即作废，再点需要重新预览。改名后建议回「剧目库」重新扫描并检查。

### 10.2 码率修复

- 先设「码率安全线（Mbps）」（默认 4）→ 点「检测码率」，逐集给出实测码率与
  `达标 / 低于安全线 / 探测不到码率`；有低于安全线的分集时「修复不达标分集」才会亮起。
- 点修复会先弹出**二次确认**，写清「即将重编码 N 集、原文件会被替换（视频与音频都会重新编码）、
  没有备份、不能撤销」，并列出前几个文件名。确认后才开始。
- 修复走「临时文件 + 原子替换」，但**仍然没有备份**。重要素材请先自行备份，或先在副本上试一集。
- 结束后给出每集「原码率 → 新码率」，失败项单列原因。结果已变化，需重新「检测码率」。

### 10.3 视频转码

**转码建议与批量规范化**（只建议，不自动执行）

- 填目标容器、码率上限（Mbps）、最大宽/高（0 表示不限）→「生成转码建议」。
- 输出：共几集、需转码几集、已合规几集；需转码的逐集给出**原因**；下面可展开查看批量 `ffmpeg` 脚本预览。
- 它给出的输出目录是预览值（剧目目录下的 `规范化/`），这一步不会写任何文件。

**执行转码**（会真的跑，耗时较长）

- 「智能微调」每集裁掉开头 1~3 帧（每次不同）；「分集重组」按场景切点把全剧重新分集，
  可填「目标集数」（留空保持原集数）。
- 输出目录留空时，先看「设置 → 默认输出目录」：设了就写到「该目录 / 剧名 / 微调输出（或 重组输出）」，
  没设才写到「剧目目录/微调输出」或「剧目目录/重组输出」；填了则写到你指定的目录。
- **输出目录不允许等于素材目录**：那种情况会覆盖原素材，界面会在输入框下直接标红拦下，
  后端在真正执行前也会再拦一次。全剧重编码，请预留时间。

### 10.4 报审包差异对比

读两份报审包的 `manifest.json`，列出改稿前后的**新增 / 移除 / 修改**文件，并给出两份报审包的
生成时间对照。它只读清单，不读素材内容，也不改动任何文件。

### 10.5 平台材料要求（示例档案）

- 内置档案是**学习示例**，不是任何平台的官方规范。
- 「对照当前剧目」会逐集对照时长、画幅、码率、编码与必需材料，输出「N 项阻断 / N 项警告」，
  或「无阻断项」。绿色=无阻断、黄色=有警告、红色=有阻断。

### 10.6 剪映草稿

- 「导出草稿」：把分集顺序与时长写成剪映草稿目录（留空写到剧目目录），结束后回填实际目录。
- 「读回草稿」：选择草稿目录，列出片段顺序、时间线起点与时长，用来和素材核对。
- 导出的草稿是**三条轨**：
  - **视频轨**：每集一个片段，**默认静音**（视频片段的音量为 0，画面保留）；
  - **音频轨**：每集一个片段，时间范围和同集的视频片段完全一致，**音量为 1**——这就是**独立原声轨**。
    视频静音 + 原声单独成轨是剪映里「视频原声分离」的形态，后面单独调人声或配乐都不用重新拆轨；
  - **字幕轨**：剧目目录里有和分集**同名**的 `.srt` 时，每条字幕生成一个文字片段，时间轴按整条草稿算。
    没有同名 `.srt` 的集不会生成字幕，整部剧都没有 `.srt` 时草稿里没有字幕轨。
- 导出选项 `includeAudio`（Rust 侧 `DraftExportOptions.include_audio`）默认是 `true`；
  改成 `false` 时**不建音频轨，视频轨保持原音量**——否则会变成静音视频加一条不存在的音频轨，
  也就是一声不响。界面上的「导出草稿」目前只传输出目录，没有暴露这个开关。
- 字幕正文会做 XML 转义：剪映的文字素材 `content` 是一段 `<font>` 包裹的富文本，正文里裸的
  `<` / `>` / `&` 会让整段解析失败，所以按 XML 1.0 的最小转义集处理并包一层 `<font>`。
  这个结构来自社区文档与开源工具的记录（例如 pyJianYingDraft 的文本素材示例），**不是官方规范**。
- 剪映草稿格式是不公开的私有 JSON、随版本变化，这只是**交接与核对**用途；
  原声轨与字幕轨能不能被剪映正确识别，只能在装了剪映的真机上确认。

### 10.7 区域擦除（试用版水印 / 台标 / 固定字幕）

- 只处理**自有素材**的硬字幕与角标；本功能不提供任何绕过版权保护或去除他人作品标识的能力。
- 试用版加水印通常是那款软件的授权手段，去掉水印后商用一般违反它的许可协议，有被追责的风险；
  最稳妥的办法是买正式版授权。
- 取帧、识别、批量都作用在**当前剧目**上，所以先到「剧目库」选一部剧。
  擦除工具是 `dossier-inpaint`：留空时从 `PATH` 与仓库的 `target` 目录查找，找不到就在「工具路径」里指定。

**工作流：取帧 → 自动识别 → 拖框微调 → 左右对比 → 勾选权利确认 → 批量**

1. **取帧**：填「取帧秒数」（默认 2 秒），点「按当前剧第 1 集取帧」。左边显示原片，右边空着等对比。
   取帧是按第 1 集的这一秒取的，预览会等比缩到宽 720 显示，但**区域坐标一律按原始分辨率保存**。
2. **自动识别**：点「自动识别」，工具会把画面里「位置固定、内容不变」的区域作为候选框填进画布。
   采样帧数在「高级参数 → 识别采样帧数」里调（默认 30，可填 2–600；调大更稳、也更慢）。
3. **拖框微调**：见下面的画布操作表。识别结果只是**候选**，最终擦哪里由你在画布上确认。
4. **左右对比**：点「预览对比」，只擦**当前的 4 秒**（从「取帧秒数」前 2 秒开始）并取同一时刻的帧，
   右图就是擦除后的效果。用它判断框画得对不对、擦干净了没有，比看整集快得多。
5. **勾选权利确认**：不勾选，批量按钮不会开工（后端也会再拒绝一次）。勾选这件事会记进本机处理台账。
6. **批量**：点「对当前剧全部集开始擦除」，任务进队列，进度到侧栏底部的「任务」里看。

**画布上怎么画框**

| 操作 | 效果 |
| --- | --- |
| 在画面上按住拖动 | 新建一个框，松手生效 |
| 按住框内拖动 | 移动这个框 |
| 按住框右下角的把手拖动 | 缩放这个框 |

框会按原始分辨率夹在画面内并取整到像素，拖出去的部分不算。松手时宽或高不足 8 像素的框会被丢掉
（多半是误点）。「清空区域」把当前所有框清掉，重新识别或重画。

**自动识别只是填候选框，不要当成结论**

- 识别不到时会提示「没有找到「位置固定、内容不变」的区域；可以手动在画面上拖框」——
  这不等于画面里没有水印，自己拖一个框即可。
- **画面里有大面积静止背景时可能误报**：纯色片头、固定机位的长镜头、一动不动的字幕版式都属于
  「位置固定、内容不变」，识别可能把背景整块框进来。把多出来的框删小或清空后手动重画。
- 判据与默认阈值见 [`WATERMARK_REMOVAL.md`](WATERMARK_REMOVAL.md) 的「自动识别静止区域」一节。

**输出在哪、进度在哪看**

- 输出目录按 `<产物根>/<剧名>/擦除输出/` 的规则拼成（产物根取「设置 → 默认输出目录」）。
  **以提交后结果区显示的「输出目录」为准**，不用自己拼。每集写一个 `<分集主名>.mp4`；
  全部集跑完后再在同目录写一份 `擦除报告.json`，里面有逐集结论、产物哈希、用到的区域和权属材料的哈希。
- 进度在侧栏底部的「任务」里：显示到第几集、每集的状态，能**暂停、终止、继续**。
  继续时会先核对已完成各集的产物哈希，对得上的集跳过、核不上的重做。
  和别的长任务一样，同一时间只跑一个任务。
- 每集开工前会重算一次源文件哈希，和提交时不一样就拒绝这一集，提示重新提交任务。
- 批量擦除的修复后端目前是本地 `column` 基线（不需要模型）；要换成 E2FGVI 这类时序模型，
  走命令行 `--inpainter worker`，参数见 [`WATERMARK_REMOVAL.md`](WATERMARK_REMOVAL.md)。

**每集的退出码**

| 退出码 | 含义 | 任务里怎么显示 |
| --- | --- | --- |
| `0` | 自动校验通过 | 「已擦除 · 自动校验通过」 |
| `3` | 需要人工抽查（有警告但不算失败） | 「已擦除 · 需人工抽查」，报告里记为 `warn` |
| `2` | 自动校验失败，画面可能没擦干净 | 这一集失败、任务停下；把框调大一点后重新提交 |
| `1` | 执行错误（工具没装、ffmpeg 报错等） | 这一集失败、任务停下，并显示工具输出的第一行错误 |

`3` 和 `0` 都算成功：`3` 只是「机器不敢替你签字」，需要你自己看一眼成片。

## 11. 模块六：设置

### 检查规则与路径

- 可改：最少集数、单集时长下限/上限（秒）、码率上限（Mbps）、是否对横屏分集给警告。
- 可改：默认输出目录（`ffprobe` 路径不在这里，见下一节「本机环境」）。
  它是**产物的根目录**：留空时产物写在各自剧目目录内；填了则按「该目录 / 剧名 / 产物名」落盘，
  多部剧各占一个子目录、不会互相顶掉。生成报审包、智能微调/分集重组、处理版本都读这个值，
  各页自己的「输出目录」输入框只是**本次运行**的临时覆盖。
- **保存后才生效**：探测与生成都读「已保存的设置」；改了没保存时，标题右侧会显示
  `有改动未保存` 徽标。表单里的临时改动不会偷偷生效。
- 「恢复默认」只回填表单为内置默认值，仍然要点「保存设置」才生效。
- 「生成报审包」页里的同名输入是**本次运行覆盖**，不改变设置。
- 素材根目录不在这一页填：扫描成功后应用会自动记住，下次启动时「剧目库」的目录框会直接回填。
- 设置只写入本机配置文件，页面底部会显示它的**实际路径**（应用配置目录下的 `settings.json`）。

### 本机环境

- 逐项列出 `ffmpeg` / `ffprobe` / `python` 的「已找到 / 未找到」与版本说明。
- **一键配置运行环境**：自动下载安装 `ffmpeg` / `ffprobe`（约 25 MB，需要联网），完成后把路径写入设置
  并重新检测；下载期间按钮会保持禁用，网络慢时可能要等几分钟。**这个按钮在 macOS 与 Windows 上出现**；
  下载后会先校验 SHA-256，不符就删文件并换下一个来源（Windows 有 gyan.dev 与 BtbN 两个来源），
  全部失败时错误信息里逐条列出每个来源的原因与手动安装步骤。Linux 上同一位置显示的是手动安装指引
  （`sudo apt install ffmpeg`），装好后再用下面的「ffprobe 路径」指定位置。
- **重新检测**：立刻再跑一遍环境探测。
- **ffprobe 路径（高级）**：手动指定可执行文件位置；留空则由应用按「设置里的路径 → 安装目录 → 系统
  `PATH`」自动查找。改完保存设置会自动重新检测。
- **中文字体文件**（「处理版本」那一组）：水印、AI 标识、封面文字要用的字体，可从 `ttf` / `otf` / `ttc`
  里选。**留空时**自动找系统字体（macOS 苹方、Windows 微软雅黑、Linux 上的 Noto CJK 等）；
  指定的文件不存在时会直接报错，不会偷偷换成别的字体。生成处理版本前若提示「没找到中文字体」，就填这一项。
- **只用软件编码**（「处理版本」那一组）：默认不勾——有可用的显卡编码就用（更快）；
  某一集显卡编码失败时会自动改用软件编码重做，任务列表和版本说明里都会写明。
  **什么时候要勾**：显卡编码在本机跑起来不稳、画面异常或反复退回软件编码时，勾上就一律用软件编码，
  省掉每次失败的尝试。改动保存后，对之后开始或继续的任务生效。
- **出错时上报诊断信息**：**默认关闭**。勾上并保存后，应用出错时会向服务端发一条诊断信息，
  帮我们定位问题；不勾就**完全不上报**。开与不开都不影响任何功能。

  只发四样东西：**错误码**、**应用版本**、**操作系统**、**出错的位置**（哪个模块，例如「上传」「积分」）。
  **不上报**邮箱、文件路径、剧名或视频内容——错误消息本身也不发（它可能带路径或剧名）。
  想让我们看到具体细节，请截图发过来。
  服务端那边同样按白名单收：多传的字段会整条被拒，带斜杠的「位置」会被清空。

### 剪映

设置页左栏的「剪映」子页用来定位剪映专业版，工具箱的草稿导入 / 导出要用它。

- 「自动检测」：先看设置里手动指定的目录，再看平台默认位置，都没有就报未安装。
  **手动指定过就不回退到默认位置**——你显式指定过，说明默认位置不对，悄悄换掉会让人以为设置生效了。
- 各平台的默认位置：
  - macOS：安装目录 `/Applications/JianyingPro.app`，草稿目录
    `~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft`，版本号读应用包里的 `Info.plist`；
  - Windows：安装目录 `%LOCALAPPDATA%\JianyingPro`（判断依据是里面有 `JianyingPro.exe`），草稿目录
    `%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft`，版本号读安装目录下的纯文本
    `version`。
- **Windows 的这两个默认路径是推断值**：网上只有间接说法，没有官方文档，所以 `jianying_detect` 的返回值里
  带一个 `defaultIsInferred` 标记（Windows 上为 `true`，手动指定过安装目录之后变成 `false`）。
  它的意思是「这个路径没人核实过」——**找不到剪映时请手动选安装目录**，不要当成「本机没装剪映」。
  现在界面在探测不到时只提示「未在 … 找到剪映专业版」，手动选择那一步要你自己做。
- 检测结果会回填安装目录、版本号；草稿目录作为输入框的占位提示，留空就用探测到的默认位置。
  手动指定的目录不存在时**不会**悄悄回退到默认位置。点「保存到设置」写入本机配置文件。

### 关于

显示版本号，并说明素材和报审包只保存在本机、不上传；账号、使用权和设备绑定记录保存在服务端。
（例外是「服务端处理」：那一页会按你的操作把视频传到服务端，见 [9](#9-模块四服务端处理)。）

## 12. 任务

侧栏底部的「任务」是处理版本的生成队列。同一时间只跑一个任务（视频编码本来就吃满 CPU/GPU，
并行只会都变慢），后面的任务依次排队。入口上会显示还没结束的任务数，卡片里能看到进度条、
每集的状态和说明（画质分数、实际用的编码器），也能直接「打开目录」。

### 六种状态

| 状态 | 含义 |
| --- | --- |
| 排队中 | 已提交，等前面的任务做完 |
| 运行中 | 正在跑，卡片里会显示「正在处理 第NN集.mp4」 |
| 已暂停 | 你点了暂停，或应用重启后没做完的任务统一落到这个状态 |
| 已终止 | 你点了终止，或重启前就被终止了 |
| 完成 | 全部步骤做完 |
| 失败 | 某一步出错（画质低于下限、源文件被改动、ffmpeg 报错等），卡片上会写清原因和停在哪一集 |

### 三个按钮

- **暂停**：排队中的任务立刻停下；运行中的任务是「**当前这一集做完再停**」，
  点下去会提示「会在当前这一集做完后暂停」，不会打断正在编码的那一集。
- **终止**：**立刻**结束正在跑的 `ffmpeg` 进程，并删掉这一集的半成品；已经做完的集保留。
  会先弹一次确认。
- **继续**：已暂停、已终止、失败的任务都能继续。继续时会核对已完成各集的产物：
  **产物还在、内容没被改过的集直接跳过**，产物缺失或哈希对不上的集重做。

看任务、暂停、终止这三件事任何时候都能做，不要求账号还有有效使用权——即使授权恰好到期了，
也能把正在跑的编码停下来。

### 重启之后

关掉应用再打开，「任务」里没做完的任务会停在**已暂停**——不会在你不知情时自动开工，
要手动点「继续」才接着跑。任务进度、每集的产物记录都保存在本机，重启不丢。

> 「任务」里只有**本机**跑的活（处理版本、区域擦除批量）。**服务端处理的任务不在这个队列里**：
> 它在服务端排队执行，进度、取消、产物下载都在「服务端处理」页自己的任务卡片上（见 [9](#9-模块四服务端处理)）。

## 13. 积分与充值

积分只花在三处**付费功能**上：**生成报审包**、**处理版本**和**服务端处理**，都是按集扣，一集 5 积分。
入口在账号菜单（侧栏底部的账号区）的第一项「积分与充值」，里面有余额、流水、充值和邀请码。
首页的新手引导里也有一步「充值积分」，余额大于 0 就会自动打勾；点它的「去充值」按钮会直接打开这个弹窗。

### 余额与流水

- 弹窗顶部是**当前余额**，右边有「刷新」：余额是服务端按流水实时算出来的，不是本地记的数字；
- 下面的「积分流水」按时间新到旧列出**时间 / 变动 / 说明**三列。变动带正负号，加积分是绿色、扣积分是红色；
- 流水里每一行的「说明」按种类给：充值、预扣、退还、奖励。**预扣的三态**在这里看得最清楚：
  - `预扣中：…`：这笔钱已经从余额里减掉了，但服务端还在确认结果。报审包与服务端处理会短暂出现这个状态；
  - `已消费：…`：定案了，这笔钱就是花掉了；
  - `已退还：…`：这笔预扣最后没花，钱已经退回余额（另有一条正的「退还」流水）。
- 预扣超时被回收时，原来那行也标成「已退还」，另外多一条正数流水，说明写的是「预扣超时未结算，已自动退还」。
- 余额、流水的具体数字以服务端为准；界面上不自己算，避免两边对不上。

### 充值

1. 在「充值」下选一个档位（按钮上写着「多少积分 · 多少钱」）。档位由服务端配置，下架的档位不会出现在这里；
2. 点档位后订单就创建好了，弹窗里会显示**应付金额、到账积分**，以及一行收银台地址；
3. **当前只有本地模拟支付，没有接真实渠道**。那一行地址指向服务端自己的模拟收银台页面
   （形如 `/pay/mock/checkout?out_trade_no=…`；只显示相对路径时，在前面拼上服务端地址再打开）。
   在这个页面上点「支付成功」就相当于走了一次真实的支付回调；页面上还有「重复回调」「支付超时」
   「伪造金额」三个按钮，分别用来验证不会重复入账、订单会关闭、金额不符会被拒绝。
   **这条链路不涉及任何真实资金**；
4. 回到应用点「**我已完成支付**」：它会拿订单号向服务端主动查一次单，这是「回调丢了」的兜底。
   如果这笔订单已经入账，会提示「这笔订单已经到账过了」并刷新余额；如果服务端还没收到回调，
   就按渠道去查——**模拟支付没有渠道侧可查**，所以这种情况下会直接提示渠道还没配置好（见下面的说明）；
5. 到账后余额和流水都会刷新。

**关于「我已完成支付」**：它不会、也不能把订单改成已支付——服务端只按渠道给的结果入账，查不到就如实说没查到。
**模拟支付渠道没有「渠道侧」可查**，所以在模拟支付下点它只会看到一句「这个支付渠道还没配置好，暂时不能用」，
这不是故障（服务端的原始说明是「模拟支付没有渠道侧可查单」）。要看余额变化，走上面第 3 步的模拟收银台。

### 邀请码

- 「邀请好友」里展示的是**我的邀请码**（只读输入框，点「复制」复制走），由账号 ID 派生，不会变；
- 把码发给朋友，对方**注册时填上**（注册表单里有「邀请码（可选）」一栏，对应服务端注册接口的可选字段 `invite_code`，最长 16 个字符）；
  填错不会让注册失败，只是这次不算邀请；
- **要等对方完成首次充值**，双方才各得一次奖励。界面上会写明当前的奖励规则与每人最多奖励几次
  （默认 50 / 20 积分、每人最多 20 次）；
- 下面一行是战绩：「已邀请 N 人 · 已得奖励 X 次（共 Y 积分）」；
- 防刷是自动的：一个账号只能被邀请一次、同一台电脑最多给一个账号当邀请来源、没付过钱不发奖励、
  每个邀请人的奖励次数有上限。

## 14. 常见问题与排错

| 现象 | 原因与处理 |
| --- | --- |
| 顶部横幅提示「运行环境未就绪」 | macOS / Windows：点横幅上的「一键配置运行环境」自动下载安装（约 25 MB，需要联网，装前校验 SHA-256）。Linux：按横幅给出的命令手动安装 FFmpeg（含 `ffprobe`）并确保在 `PATH` 中 |
| 右上角提示「缺少 ffmpeg / ffprobe」 | 点标签或顶部横幅；或在「设置 → 本机环境」里指定 `ffprobe` 路径后保存 |
| 一键配置后仍提示未就绪 | 应用装完会自动重测；若仍缺，检查是否杀软拦截下载，或手动在「设置 → 本机环境」填 `ffprobe` 路径并保存 |
| 一键配置报「已尝试 N 个下载来源都失败」 | 这是**多来源**逐个试过都失败的结果：错误信息里列了每个来源各自的失败原因（「网络或 HTTP 失败」是连不上，「哈希不符」是下到的文件与钉住的版本对不上，后者更严重）。按提示里的手动安装步骤做，或换个网络重试 |
| 一键配置报「哈希未配置」 | 应用里钉住的校验值还没被维护者填入（只可能出现在开发版）。为安全起见应用**不会**跳过校验直接安装；按提示手动安装，或等维护者补上常量后再用一键配置 |
| 一键配置报「系统版本太旧」 | Windows 10 1803 之前的系统不带 `curl.exe` / `tar.exe`，需要手动安装 |
| 找不到「一键配置运行环境」按钮 | 这是刻意隐藏的：该功能只在 macOS 与 Windows 上提供，Linux 请按横幅/设置页给出的命令手动安装 |
| 「探测并检查」失败并提到 ffprobe/启动/PATH | 同上；错误信息里会点名本机缺的是哪个工具 |
| 「请先选择剧集素材根目录」 | 先填/选根目录再点扫描 |
| 提示「报审包目录已存在」 | 换一个输出目录，或先把旧报审包移走/改名（不会覆盖已有材料） |
| 提示「这一步需要联网」 | 生成报审包、开始生成处理版本都必须联网（生成报审包执行前还会联网刷新一次授权）；断网时先连上网再点 |
| 提示「这个账号还没有使用权」/「使用权已到期」 | 账号没兑换过卡密或使用权已到期；去「授权卡密」页兑换或续期后再生成 |
| 生成时报「没有有效的使用权」 | 执行前本机授权是好的，但服务端复核时使用权已不生效（例如刚在别处到期）；兑换或续期后重试 |
| 提示「找不到本机文件 …」或「… 在提交后被改动或调换过」 | 生成期间把分集移走、改名、改内容或两集对调了。文件放回原位、内容恢复后**重新生成**；本次不会留下半个目录 |
| 包里的 PDF 上有「样章 · 未签署 · 无法律效力」和斜向水印 | 这是**占位章**，不是盖章文件。正式报审前要换成盖章版本，或在生成前上传已盖章的扫描件代替它 |
| 上传扫描件时提示「只能是 PNG、JPEG 或 PDF」/「太大」/「页数要一致」 | 扫描件只认这三种格式、单份不超过 5 MB，页数必须和原文档一样。压缩或重新扫描后再选 |
| 生成时报「服务暂时不可用」 | 服务端要么找不到报审包生成工具，要么签章服务不可用。稍后重试；持续出现请联系管理员 |
| 「输出目录不能是素材目录」 | 转码输出不能写回素材目录；清空让应用写到剧目目录下的子目录，或另选目录 |
| 「输出视频不能与输入视频相同」 | 命令行擦除（`dossier-inpaint`）的输入输出必须不同，改输出路径。界面上的区域擦除按剧自动分目录，不会撞上源文件 |
| 区域擦除提示「没有找到「位置固定、内容不变」的区域」 | 自动识别没找到候选。可以在画面上手动拖框；也可以调大「高级参数 → 识别采样帧数」再试一次 |
| 区域擦除的候选框明显不对 / 框住了整片背景 | 大面积静止背景也会满足「位置固定、内容不变」。清空区域后手动重画，或删掉多余的框 |
| 擦除任务某一集停下并提示校验未通过 | 退出码 `2`：画面可能没擦干净。把框调大一点后重新提交；只有退出码 `3` 才需要在人工抽查后放行 |
| 擦除任务提示「源文件和开始擦除时不一样了」 | 分集在提交任务之后被改动或替换过。恢复原文件后重新提交任务 |
| 改名按钮是灰的 | 需要先「预览改名计划」，且已有 `待改名` 项、当前没有别的任务在跑 |
| 提示「已经有任务在进行」 | 上一个耗时操作还没结束，等进度条走完再点 |
| 某个按钮点了没反应 | 长任务开始后所有耗时按钮会统一置灰，这是防止重复执行，不是卡住 |
| 检查结果长期是 `尚未探测` | 只扫了目录没点「探测并检查」，或探测失败（看失败原因那一行） |
| 码率修复后仍提示低于安全线 | 修复结果已变化，需要重新「检测码率」；个别失败项会在结果里列出原因 |
| 「探测不到码率」 | 该文件本身没有可用码率信息，需要人工确认 |
| 处理版本提示「这部剧已经有处理版本」 | 一部剧只保留一套处理版本。想重做要先删掉旧的版本目录，再重新「预览计划」并重新申请配方 |
| 处理版本提示「画质低于下限…这一集不交付」 | 这一集没通过配方里的画质下限，输出文件已删掉。可以先「继续」再试一次；要换更轻的档位，得先删掉这次的版本目录再重新开始 |
| 处理版本提示「本机没找到中文字体」 | 画面上要写字（水印、AI 标识或封面文字）但找不到字体。去「设置 → 本机环境」的「中文字体文件」里指定一个 `.ttf` / `.otf` / `.ttc` 并保存 |
| 处理版本提示「权属材料文件的内容变了」 | 声明过的证书 / 授权书被改过或移走了，回「处理版本」页重新声明 |
| 处理版本提示「源文件和开始生成时不一样了」 | 分集在申请配方之后被改动过。恢复原文件后点「继续」；换素材只能删掉这次的版本目录重做（重做要重新申请配方） |
| 任务一直停在「已暂停」 | 应用重启过，没做完的任务一律先停下，点「继续」就会接着跑 |
| 提示「积分不足，请先充值」 | 余额不够这一步要扣的积分。这个提示和「没有使用权」是两回事：去账号菜单的「积分与充值」充值后再重试。申请配方时余额不足**什么都没生成**，充值后可以重新申请 |
| 充值后余额没变 | 充值要等服务端的支付回调到账。回调可能因网络或重启延迟甚至丢失：理论上可以点「我已完成支付」主动查一次单，但**模拟支付渠道没有渠道侧可查**，这一步会直接报「渠道还没配置好」。请回模拟收银台页面确认回调已经发出（页面上会显示「回调被接受」和本次入账多少积分），再点「刷新」看余额 |
| 处理版本失败了，积分能退吗 | **不能**。处理在本机执行、视频不上传，服务端看不到处理结果，无法判断是真失败还是想白用一次。报审包与服务端处理不同：那两种是服务端执行的，失败会自动退还预扣的积分 |
| 「我已完成支付」提示「这个支付渠道还没配置好，暂时不能用」 | 这是模拟支付渠道的真实限制，不是故障：本地没有「渠道」可查，服务端的原始说明是「模拟支付没有渠道侧可查单」。请到模拟收银台页面点按钮发出回调，再回来看余额 |
| 顶部红色横幅「这个版本已停止支持」 | 你装的版本低于服务端要求的最低版本。这时**除首页和设置外的功能都会被挡住**，只弹出提示不算数——必须先更新。点「下载并校验升级包」，通过校验后点「现在安装」，系统安装器会完成安装并重启应用。没有按钮时说明管理员还没填下载地址，请联系客服 |
| 顶部黄色横幅「有新版本可用」 | 只是提示，不影响使用。想升级就点横幅里的「下载并校验升级包」 |
| 公告一直显示「暂无公告。」 | 公告现在来自服务端。断网、服务端没起、服务端版本还没这个功能，都会这样显示。连上网重启一次应用再看看；一直没有就要问运营是不是还没发公告 |
| 升级包下载完提示「签名无效，这可能不是官方发布的包」 | **不要安装**。这可能是下载地址被换过，或包本身不是官方发布的。联系我们重新下载。校验不通过的文件会被自动删掉 |
| 升级包下载完提示「暂时无法更新：升级包没有签名，拒绝使用」 | 管理员在版本策略里没填签名。签名是必须的——只填地址和校验值不够，客户端不做「降级成只验哈希」。请反馈给运营 |
| 升级包下载完提示「校验不通过…已删除」 | 下载过程中文件损坏或被替换过。重新下载一次；反复出现请联系我们 |
| 流水里有一条「预扣中」一直不动 | 报审包与服务端处理都会短暂出现预扣；超过 2 小时一直没结算的预扣会被自动回收：原来那行标成「已退还」，另外多一条正数流水，说明是「预扣超时未结算，已自动退还」。查一次余额就会顺带触发这次清理（点「刷新」即可）。处理版本不会出现预扣（它在消费配方时一次扣定） |
| 服务端处理：上传断了怎么办 | 再点一次「开始上传」即可。同一集没传完时程序会接着用上次的上传会话，先问服务端哪些块已经有了，然后只补缺的那些块，已经传过的不重传。换了另一集就是新的一次上传 |
| 服务端处理：提示「积分不足，请先充值」 | 提交时服务端会先预扣这一单的积分，余额不够就**不会建任务**。去「积分与充值」充值后重新提交即可。这个提示与「没有使用权」是两回事 |
| 服务端处理：任务失败了钱退不退 | **退**。任务失败（或被取消）时，提交时预扣的那笔积分会原路退回余额，流水里是多一条正的「退还」、原预扣标为「已退还」。这跟本机处理版本相反——那个不退，因为视频没上传，服务端看不到成败 |
| 服务端处理：产物下载链接打不开 | 下载链接是**短时的**（15 分钟）。过期后回任务卡片点「刷新」重新取一次；如果提示产物已被清理，那是服务端的保留期到了 |
| 服务端处理：提交后一直「排队中」 | 服务端没有空闲 Worker 时任务就停在队列里。稍等再点「刷新」；一直不动请联系管理员看服务端队列 |

如果应用无响应：先等进度条结束（重编码与擦除可能数分钟）；确认无任务后再操作。

## 15. 已知限制

- 界面**不做**素材的剪切/合成，转码与重编码只做规范化与分集重组；时长/内容层面的修改请回剪辑软件。
- 「平台材料要求」是内置示例档案，不是官方规范；请替换为平台方最新要求后再使用。
- 擦除是实验能力：小掩码（角标/窄字幕条）精度最高，大面积或复杂背景需要人工抽查；
  缺少模型 worker 时部分后端不可用。界面上的批量擦除固定用本地 `column` 基线后端。
- **静止区域检测会误报**：判据是「位置固定、内容不变」，所以大面积静止背景（纯色片头、
  固定机位长镜头、不动的版面）也可能被框成候选。识别结果只是候选，必须在画布上人工确认。
- 命令行擦除的进度粒度是**每 30 帧一条**（管线按片段上报），不是逐帧；`--progress-json` 的进度流会成段往前走。
  界面的批量擦除按「第几集」给进度。
  另外阶段内还没拿到总量时（素材未写 `nb_frames` 等）会先按不确定进度显示，拿到帧数后自动切换。
- 剪映草稿格式不公开、随剪映版本变化，读回功能可能受版本影响。
  **草稿里的原声轨与字幕轨只能在装了剪映的真机上确认**：本模块只按社区记录的字段写出骨架，
  没有官方规范可对照。
- **Windows 上的剪映安装目录与草稿目录是推断值**，没有官方文档核对过；探测不到时请手动指定目录，
  不要当成「本机没装剪映」。
- 报审包生成不做增量更新：目标目录已存在就拒绝，需要你显式换目录。
- 生成报审包和开始生成处理版本都**必须联网**，且账号要有有效使用权；断网时其他本地功能照常可用，
  只有这两步会被挡下（处理版本的暂停后续跑不用联网）。服务端处理整页都要联网（见 15 的对应条目）。
- 服务端签发的成本配置表与内容权属声明默认是**占位章**（未签署、无法律效力），不能直接拿去报审。
  手头有已盖章的扫描件时可以在生成前上传（可只给其中一份）代替占位章；没上传的那份仍是占位章，
  结果里会逐份标明。桌面端不核验扫描件的真伪，只保证它原样贴进 PDF。
- 检查规则可配置，但**规则再严也代替不了人工复核**：`材料可用` 只表示无失败项。
- **一部剧只保留一套处理版本**：版本目录已存在时「开始生成」会被挡下，提示「这部剧已经有处理版本」。
  想重做（换档位、改模板、换素材）要先自己删掉旧的版本目录再重新预览、重新申请配方。
- 处理版本**不保证不被平台降权**：它按服务端配方做细微处理，但平台的判定规则不公开、随时可能变，
  要不要用、用哪一档请自己判断。
- **硬件编码在本机 Linux 上没验证过**：Windows / macOS 上的显卡编码由平台信号常开、再由
  `ffmpeg -encoders` 列表与单帧实测把关；Linux 上要求对应的设备节点（`/dev/nvidia*`、
  `/dev/dri/renderD*`、`/dev/video*`）在，才可能选中 NVENC / VAAPI / V4L2。
  本项目的 Linux 构建机上 `h264_vaapi` 就是初始化失败、退回软件编码的。
  硬件编码失败会自动改用软件编码，也可以在「设置 → 本机环境」里直接勾「只用软件编码」。
- **充值目前只有本地模拟支付**：没有接任何真实收款渠道，页面上不会出现真实的付款方式，
  模拟收银台的按钮也不涉及真实资金。真要收款得先把渠道接上（见后面两条）。
- **微信支付个人主体接入不了**：商户号对主体类型有要求（个体工商户 / 企业等），而且 APIv3 没有官方沙箱，
  所以本期只留了接口，选它下单会直接报「未配置 / 还没实现」。
- **支付宝要先有沙箱凭证和公网地址才能联调**：除了 App ID 与密钥，还得给服务端配一个能从公网访问的
  对外地址（本机开发要内网穿透），否则下单会提示「没有配置对外地址」。占位实现目前连凭证配齐了也不下单，
  会明确报「还没实现」。
- **改价与改档位在管理后台做**：积分单价（现在一集 5 积分）和三档充值（10 元 100 积分 /
  50 元 550 积分 / 200 元 2400 积分）都可以在管理后台的「价目与档位」里改，不需要重新部署。
  **改价只影响之后签发的配方与新下的订单**：已经签发的配方在签发时就把价格定死了，
  已经下的订单也按当时的金额算——所以改价不会让用户已买的东西变价。
- **处理失败不退积分**：这不是缺陷，是设计——视频只在本机处理、服务端判断不了成败。
  申请配方前请确认素材、档位和模板都已经定下来。
- **服务端处理一次只处理一集**：服务端按集计价，多集上传要排队，这一版先把「传一集 → 处理一集 → 下载」走通。
- **服务端处理的产物用短时链接下载**：链接 15 分钟内有效，过期要回任务卡片点「刷新」重新取；
  产物本身在服务端也有保留期，过期会被清理，要的东西及时下载回来。
- **服务端处理需要联网**：上传、提交、查状态、下载都要联网，断网时这一页用不了。
  已经提交到服务端的任务不受影响，联网后回来看结果即可。
- **注册时填错邀请码不会补发奖励**：绑定只在注册那一刻发生，事后没法补绑。
  如果注册时忘了填，这次邀请就算不上，双方都不会有奖励。
- **管理后台没有二次验证（MFA）**：管理后台只有邮箱 + 密码登录，没有短信 / 验证码 / 一次性密码，
  会话 8 小时后失效。它只给运营人员用，普通用户用不到；这条列在这里是为了把已知缺口写清楚。
- **自动更新的最后一步要你自己点安装器**：程序会下载、校验（大小 + SHA-256 + 签名）并把安装包交给系统，
  但**不会自己替换正在运行的程序**（Windows 会锁住运行中的 exe，macOS 换掉二进制会让签名失效）。
  所以会出现「下载完弹出一个安装器窗口」这一步，需要你点确认；**重启也由安装器完成**，不是程序自己重启。
- **版本过旧会真的拦住功能**：低于最低支持版本时，除首页与设置以外的功能都不能用
  （只弹横幅不算数——点掉提示就继续干活，那「强制更新」等于没做）。
  首页与设置仍然可用，因为要在那里看提示、下载并安装更新；兑换卡密也不受影响。
- **公告与功能开关由服务端下发**：拉不到时按「空公告、开关全开、不强制更新」降级，
  所以断网时功能不会有任何变化——只是看不到公告、也收不到强制更新的通知。
- **「出错时上报诊断信息」默认关闭**：打开后只上报错误码、版本、系统和出错模块，
  没有错误详情。想让我们看具体内容，仍然需要你截图。

## 16. 隐私与合规边界

- 应用访问网络只有这几种情况：① 账号登录、授权刷新、生成报审包、开始生成处理版本时申请与消费处理配方
  （联网请求服务端）；② **服务端处理**时上传分集视频、查任务状态、下载产物（见 [9](#9-模块四服务端处理)）；
  ③ 你**主动点击**「一键配置运行环境」时下载 **第三方构建**的 ffmpeg 压缩包
  （macOS 是 evermeet.cx，Windows 是 gyan.dev / BtbN；下载后按代码里钉住的 SHA-256 校验，
  不符就删掉并换下一个来源）；
  ④ 启动本机 `ffprobe` / `ffmpeg` 等外部进程本身不联网。
  另有两条**不含任何个人数据**的请求：⑤ 每次启动拉一次公开的客户端配置（公告、功能开关、版本要求），
  不需要登录、也不带账号信息；⑥ 只有你在设置里**主动打开**「出错时上报诊断信息」之后，
  出错时会发一条含错误码、版本、系统与出错模块的诊断上报（默认关闭，详见 [11](#11-模块六设置)）。
  **报审包与处理版本从不上传素材文件**：生成报审包时只把文件名、大小、SHA-256 和探测规格发给服务端；
  申请处理配方时只发任务哈希（由分集文件哈希、模板哈希、权属材料哈希和档位算出来）、
  档位和固定规格名 `universal`，分集视频、封面、简介都留在本机。
  **只有你主动点「服务端处理 → 开始上传」时，那一集视频才会被传到服务端**：文件按 8 MiB 分块上传，
  服务端拼好后核对整文件校验值；它留在服务端跑任务与存放产物，到期由服务端按保留期删除。
- 设置里填写的公司、联系方式只出现在「生成报审包」页的表单里（**不写入本机配置文件**），
  生成时随成本表单发给服务端用于生成成本配置表；服务端只存报审包的元数据
  （账号、机器码、生成时间、签章方式、集数、清单哈希），不保存文档内容，审计日志里也不记剧名、
  公司名、联系方式原文。这些内容会照你填写的样子写进本机报审包（成本表、权属声明）。
- 剧备只整理**使用者提供的真实材料**，固定包含内容权属声明模板，但**不伪造**签名、印章或时间戳；
  `manifest.json` 是完整性清单，不是官方审核回执。占位章会明确标出「未签署、无法律效力」。
- 擦除功能仅限自有素材；不提供 DRM 绕过，也不处理他人作品的版权标识。
- 处理版本用到的权属材料**只在本机留记录**（路径 + 校验值，写进剧目目录的 `.dossier/rights.json`
  和本机处理台账），不核验真伪、也不上传材料内容；背景音乐要不要用、有没有授权由你勾选并负责。
- 本项目定位为技术学习与交流的示例，文中的报审格式、平台要求与发布流程都不构成合规或法律意见。

## 附录 A：报审包目录结构

```text
报审包/
├── 01_剧集信息/
│   ├── 剧名.txt
│   └── 简介.txt
├── 02_封面海报/
│   └── 封面.jpg
├── 03_分集清单/
│   └── 分集清单.csv
├── 04_成本配置表/
│   ├── 成本配置表.md
│   └── 成本配置表_未签署.pdf      # 占位章，未签署、无法律效力
├── 05_权属声明/
│   ├── 内容权属声明.txt
│   └── 内容权属声明_未签署.pdf    # 占位章，未签署、无法律效力
├── 06_分集视频/        # 仅在勾选「复制分集视频进报审包」时生成
│   └── 第01集.mp4
├── manifest.json
└── manifest.sig
```

`manifest.json` 记录 `schema`（现在是 `drama-dossier/package@2`）、报审包 ID、剧名、生成时间、
账号与机器码、是否 AI 辅助、是否复制分集、签章方式与两份未签署文档，以及包内每个文件的
`path` / `sizeBytes` / `sha256` / `source`；不复制进包的分集登记在同级的 `references` 里。
`manifest.sig` 是服务端对 `manifest.json` 原始字节的 Ed25519 签名，组装前先验签。
完整字段见 [`MATERIAL_SPEC.md`](MATERIAL_SPEC.md)。

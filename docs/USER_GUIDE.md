## 1. 这是什么

剧备是一个**本地优先**的桌面应用：素材、检查报告和生成出来的报审包都留在你自己的电脑上，
**素材本身不上传**，也不做云端同步。

它帮你把这几件重复劳动自动化：

1. 按约定扫描本机的剧集素材目录，认出「一部剧 = 一个子目录」；
2. 调用本机 `ffprobe` 读取每一集的时长、分辨率、编码、帧率、码率；
3. 按可解释的规则给出检查结论（哪些缺失、哪些需要人工确认）；
4. 生成编号清晰的报审包目录 + 由服务端签名、桌面端验签后组装的完整性清单 `manifest.json`；
5. 按服务端签发的配方，给一部剧生成一套通用处理版本（带画质检测，可暂停续跑）；
6. 附带一个后期工具箱（改名、码率修复、转码、差异对比、草稿交接、字幕/角标擦除）。

**必须联网才能用的功能只有两处**（账号登录、兑换和刷新授权本来也要联网）：

- **生成报审包**：要登录账号，并且账号要有**有效使用权**。发出去的内容只有剧目信息、
  成本表单和各文件的**文件名、大小、SHA-256 与探测规格**——分集视频、封面、简介**只发校验值、不上传文件**。
  服务端按这些信息生成文档、给清单签名，文件回到本机后再由桌面端组装成报审包；
- **开始生成处理版本**：同样要登录账号和有效使用权，要向服务端申请一份配方（配方只能用一次；
  预览计划、暂停后续跑都不用联网，续跑用的是本机保存的配方原文）。

这两步都只发文件的校验值和任务描述，**素材文件始终不上传**。

**它不做什么**：不代你填真实信息、不伪造签名/印章/时间戳、不替代平台审核、不绕过任何版权保护。
规则里的阈值与「平台档案」都是**学习示例**，接入真实业务前必须换成平台方最新规范。

## 2. 装好之后先做一次环境自检

剧备自己不含视频工具，需要本机有 **FFmpeg（必须包含 `ffprobe`）**。可以自己装，也可以让应用帮你装。

- 启动后，如果缺少工具，窗口**顶部**会出现一条**运行环境横幅**，上面直接带「一键配置运行环境」按钮：
  点一下会自动下载安装 `ffmpeg` / `ffprobe`（约 25 MB，需要联网），装好后路径自动写入设置并重新检测；
  环境就绪后横幅自动隐藏，不再占版面。**不用等你点了按钮才发现跑不通。**
  - 该按钮**目前仅在 macOS 上出现**（下载 evermeet.cx 的官方构建，会用到系统自带的 `curl` 与 `unzip`）。
    Windows / Linux 上**不会**显示这个按钮，横幅与「设置 → 本机环境」会改成给出对应平台的手动安装命令：
    Windows 用 `winget install Gyan.FFmpeg`（或到 gyan.dev 下载后把 `bin` 加入 `PATH`），
    Linux 用 `sudo apt install ffmpeg` / `sudo dnf install ffmpeg`。
  - Apple 芯片（Apple Silicon）首次使用若提示 CPU 架构不匹配，请先在终端执行
    `softwareupdate --install-rosetta --agree-to-license` 安装 Rosetta 2，再重新点击一键配置。
- 窗口右上角另有一个**常驻环境标签**，随时反映状态：
  - `本机环境就绪`（绿）：可以正常扫描、探测、生成；
  - `缺少 ffmpeg` / `缺少 ffprobe`（红）：还没找到，点一下跳到「设置 → 本机环境」看详情；
  - `环境异常：ffmpeg / ffprobe`（黄）：找到了但不可用（例如路径指向了别的程序），同样点标签查看。
- 「设置 → 本机环境」里除了「一键配置运行环境」，还有「重新检测」，以及一个高级项
  「ffprobe 路径」（例如 `/opt/homebrew/bin/ffprobe`、`C:\ffmpeg\bin\ffprobe.exe`）。
  **留空时**应用按「设置里的路径 → 安装目录 → 系统 `PATH`」的顺序自动查找。

缺 FFmpeg 时仍然能做的事：**扫描剧目**（只读文件名与体积）。会失败的事：**探测并检查**、
生成报审包、码率修复、执行转码、生成处理版本（这一页顶部会直接给出「下载运行环境」入口）。
注意「一键配置运行环境」是应用里**唯一**会主动下载文件的动作，
且只下载官方的 ffmpeg 压缩包。

## 3. 界面总览

界面是一列左侧导航 + 五块工作区，任何时刻只显示一块；此外侧栏底部还有一个常驻的「任务」入口：

| 区域 | 作用 |
| --- | --- |
| 剧目库 | 选素材根目录 → 扫描 → 点选一部剧 → 探测并检查 |
| 生成报审包 | 填写出品方、投资额等信息并生成报审包 |
| 处理版本 | 声明权属材料、调版本模板，按服务端配方给一部剧生成一套通用处理版本 |
| 工具箱 | 改名、码率修复、转码、报审包对比、平台档案、剪映草稿、擦除 |
| 设置 | 检查规则阈值、默认路径、本机环境、关于 |
| 任务（侧栏底部） | 处理版本的生成队列：看进度、暂停、继续、终止 |

界面顶部还有这几样东西：

- **运行环境横幅**：只在缺少 `ffmpeg` / `ffprobe` 时出现，装好即隐藏。macOS 上带「一键配置运行环境」
  入口，其他平台改为直接给出该平台的手动安装命令；
- **常驻环境标签**（右上角）：随时显示「本机环境就绪」或缺哪个工具，点一下跳到「设置 → 本机环境」；
- **当前剧目**标签：提醒你现在所有操作都作用在哪一部剧上；
- **进度条**：所有耗时操作都会显示。逐集探测能算出总量时是**确定进度**（`正在探测分集 3/12：第03集.mp4`），
  转码与码率修复按「第 3/8 集」这类单元显示确定进度；处理版本在预览计划时逐集核对哈希，同样显示
  「正在核对第 3/12 集」；擦除按「第几段 + 已完成多少帧」显示确定进度
  （`擦除中 · 逐片段修复画面（第 2/2 段）：已完成 1234/5000 帧`）。
  真的算不出总量时才退回**不确定进度 + 已用秒数**；
- **提示条（Toast）**：失败用红色并统一带「出错了：」前缀，停留时间也更长（9 秒，成功为 4.5 秒）。
  除了颜色还有文字前缀，截图或投屏也能分辨成功与失败。
  路径、权限、运行环境这类**能指出下一步**的错误会直接带一个按钮（「打开设置」/「重新检测」/
  「去设置环境」），点了就跳过去，不用自己翻页找。

**长任务只允许一个**：只要有任务在跑（扫描、探测、生成、改名、码率检测/修复、转码、平台对照、
草稿读写、擦除、预览处理计划），所有耗时按钮都会自动置灰，避免重复点击把同一件事跑两遍。
想再点会提示「已经有任务在进行」。处理版本的「开始生成」只在提交那一刻占用这个开关：
提交完就交给「任务」队列在后台逐集跑，你可以照常去别的页面操作。

## 4. 五分钟上手

1. 打开应用 → 左侧「剧目库」。首次进入时中间会有一份**三步引导**（选择目录 → 扫描剧目 →
   点选剧目并探测），每完成一步前面的圆圈会打勾，也可以直接点引导里的按钮走完，不必自己找入口。
2. 在「素材根目录」里输入或点「选择」挑一个目录（里面每个子目录 = 一部剧）。
   扫描成功后这个路径会**自动记住**，下次启动直接回填。
3. 点「扫描剧目」，左侧会列出找到的剧目与集数、总体积。
4. 点选一部剧 → 点右上角「探测并检查」，等待进度条走完。
5. 看「检查结果」（通过 / 需确认 / 不通过）和「分集」表，按提示补齐缺失材料。
6. 切到「生成报审包」，填出品方等信息 → 点「生成材料包」（这一步需要联网，账号要有有效使用权）。
7. 生成完可以点结果里的「打开目录」直接跳到报审包，或「复制路径」发给同事。
   注意包里的两份 PDF 是**占位章、未签署**，正式报审前要换成盖章版本。

## 5. 素材怎么准备

推荐的目录结构（根目录下每个子目录是一部剧）：

```text
素材根目录/
└── 示例短剧/
    ├── 第01集.mp4
    ├── 第02集.mp4
    ├── 封面.jpg
    └── 简介.txt
```

- 视频扩展名：`mp4`、`mov`、`mkv`、`flv`、`ts`、`m4v`、`webm`；
  图片：`jpg`、`jpeg`、`png`、`webp`；文本：`txt`、`md`。
- 剧目目录内部的**一层子目录**也会被扫描。
- 集号解析优先级：① `第12集` / `第12话` / `第12回` → ② 词边界的 `E12` / `e03` → ③ 主干里的独立数字（`show_12`）。
  解析不出集号的文件会被列入「无法解析」并保持不动（不会乱改名）。
- 封面建议 `封面.jpg`，简介建议 `简介.txt`，不少于 30 字，写清题材、主要人物、受众定位。

> 小贴士：文件名不统一时，先去**工具箱 → 批量改名**把它统一成「剧名 - 第NN集」，
> 再做探测与生成——集号解析依赖文件名。

## 6. 模块一：剧目库

### 扫描剧目

- 输入/选择根目录 → 「扫描剧目」。找不到子目录时会显示「未找到剧目子目录。」。
- 左侧剧目条目显示：剧名、集数、素材总体积。
- **切换剧目或重新扫描会作废工具箱里上一部剧的计划与结论**，防止拿旧计划点执行。

### 探测并检查

点「探测并检查」后逐集读取规格，结果分两块：

- **检查结果**：每条给出「项目 + 状态 + 说明」。状态含义：
  `通过` / `需确认`（警告，需要人工判断）/ `不通过`（缺失等失败项）/ `尚未探测`。
  右上角徽标是总览：`材料可用`（无失败项）或 `有缺失项`。
- **分集**表：集号、文件名、时长、`宽×高`、状态。探测失败的那一行直接显示失败原因。

`材料可用` 只代表**没有失败项**，警告项仍然要人工确认。

## 7. 模块二：生成报审包

这一页**需要联网**，并且账号要有**有效使用权**：执行前会先联网刷新一次授权，断网时提示
「这一步需要联网：连不上服务端，请联网后重试」；没有使用权时提示「这个账号还没有使用权，请先兑换卡密」。
发往服务端的只有：剧目信息（剧名、是否 AI 辅助）、成本表单、以及每一集的
**文件名、大小、SHA-256、探测规格**和封面 / 简介的同一组信息——**分集视频、封面、简介都不上传**。

上半部分是「本次运行覆盖」，只影响这一次；长期默认值在「设置」里。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 输出目录（本次覆盖） | 否 | 留空 = 按「设置 → 默认输出目录 / 剧名 / 报审包」落盘，设置也为空时才写到「剧目目录/报审包」。填了就生成到你指定的目录 |
| 出品 / 公司 | 否 | 写进报审包的成本表与权属声明；请填**真实**信息 |
| 投资总额（万元） | 否 | 必须是不小于 0 的数字（上限 1e9），格式错误会在输入框下就地标红 |
| 演员成本占比（%） | 否 | 必须在 0–100 之间 |
| 联系方式 | 否 | 随成本表单发给服务端，用于生成成本配置表；服务端不保存文档内容，审计日志里也不记原文 |
| 复制分集视频进报审包 | 否 | 勾选后会额外生成 `06_分集视频/`（最耗时的一步，进度条会说明） |
| 使用了 AI 辅助生成 | 否 | 如实勾选，会记进 `manifest.json` 的 `aiGenerated` |

这一页**不再单填 ffprobe 路径**：读取规格用的 `ffprobe` 统一取「设置 → 本机环境」里的配置
（留空则自动查找）。

点「生成材料包」后依次做三件事：**先重新探测一遍**（避免用过期规格）→ 逐集算 SHA-256（进度条会说明）
→ 把上面那组信息发给服务端。服务端生成文本文件、把成本配置表和内容权属声明渲染成 PDF 并盖章、
给清单签名，发回本机后桌面端**先验签**，再把分集、封面、简介放进去并**逐个重算哈希比对**，
全部对得上才写出报审包；中途失败不会留下半个目录。最后结果里给出位置、文件数与总大小，
并提供「打开目录 / 复制路径」。

几点须知：

- **生成的文档现在是占位章**：成本配置表与内容权属声明的 PDF 上是灰色虚线框 +
  「样章 · 未签署 · 无法律效力」+ 整页「草稿 · 未签署」斜向水印，文件名带 `_未签署` 后缀。
  它**不是**盖章文件，也**不具备法律效力**。正式报审前必须换成盖章版本。
- **提交之后改动或调换了分集，会被拒绝并要求重新生成。** 服务端记的是提交那一刻的文件名、大小和
  SHA-256：文件被移走或改名会提示「找不到本机文件 … 请重新生成」；内容变了或两集对调了会提示
  「… 在提交后被改动或调换过（内容和提交时不一致），请重新生成」。这两种情况都不会写出半个包。
- 目标目录**已存在**时会直接拒绝，提示「报审包目录已存在」，不会覆盖已有材料。
  这时结果区会直接给出旧包位置，可以点「打开目录」先确认；提示条上还有「换个输出目录」按钮，
  点一下就能重新挑目录再生成（旧目录始终不会被改动）。
  目录已存在会**在本机先挡下来**，不占用一次服务端生成次数。
- 生成失败时结果区用红色展示，不会与成功色混淆。
- 报审包结构与 `manifest.json` 字段见[附录 A](#附录-a报审包目录结构)与 [`MATERIAL_SPEC.md`](MATERIAL_SPEC.md)。

## 8. 模块三：处理版本

这一页给**一部剧**生成**一套**通用处理版本（只做一套，不区分平台）：输出目录是
`<产物根>/<剧名>/处理版本/`，「产物根」取「设置 → 默认输出目录」，没设时写在剧目目录下。
目录里有各集视频（和源文件同名，后缀统一换成配方给出的容器，现在是 `.mp4`）、`封面.jpg` 和 `版本说明.json`。

> 配方由服务端签发、**只能用一次**，所以「开始生成」这一步需要联网，账号要有有效使用权。
> 选档位、改模板、预览计划都只在本机算，不联网、不扣次数。

### 8.1 操作顺序

1. **选剧**：先在「剧目库」扫描并点选一部剧，本页顶部会显示当前剧目；
2. **声明权属材料**（见 8.2）；
3. **选强度档**：「轻 / 中 / 重」，档位越重变化越大、画质下限也放得越宽；
4. **填模板并保存**（见 8.3）：表单有改动时标题右侧会亮「有改动未保存」，
   预览和生成**只认已保存的模板**，所以要先点「保存模板」（不想改了可以点「放弃改动」）；
5. **预览计划**：逐集列出时长、原分辨率、有没有字幕，并列出每集要做的处理和「还不能开始生成」的原因；
   **「开始生成」只有在预览通过之后才能点**，改了档位或模板要重新预览；
6. **开始生成**：二次确认后向服务端申请一份处理配方并立即用掉，任务进入队列；
7. **去「任务」看进度**（见 11）：侧栏底部的「任务」里能暂停、继续、终止，也能打开产物目录。

### 8.2 权属材料

- 每部剧声明一次：点「选择文件并声明」，选一份**版权登记证书或授权书扫描件**（支持 `pdf` / `jpg` / `jpeg` / `png`）。
- 程序**只记下文件路径和校验值，不核验真伪**。它的作用是留一份记录、划清责任：
  声明会记进本机的处理台账，申请配方时也会把材料哈希绑进任务。
- 文件**被改动或移走**之后，本页会变成「需要重新声明」，点「重新选择并声明」即可；
  没重新声明就不能生成。

### 8.3 版本模板能调什么

模板保存在剧目目录的 `版本模板.json`，逐部剧一份，换剧会换成那一部剧的模板。

| 分组 | 可调的内容 |
| --- | --- |
| 片头 / 片尾 / 封面 | 片头视频、片尾视频（都可以不填，没有音轨的会补静音）；封面取第 1 集第几秒（默认 1 秒）；封面文字（可不填，不填就不叠字） |
| 字幕与调色 | 字幕文件夹（按集名对应 `.srt`，可不填，不填就不烧字幕）、字幕字号（像素，默认 56）、字幕离底边（像素，可不填）、调色预设（原色 / 暖色 / 冷色 / 高对比 / 低饱和五档） |
| 剧名水印与 AI 标识 | 水印文字（不填就不放）、水印位置（四角之一，默认右上角）、水印透明度（0–1，默认 0.5）；「本剧视频含 AI 生成内容」勾选框与 AI 生成合成服务提供者名称 |
| 节奏与背景音乐 | 「先按场景切点重新分集」与重新分成几集（留空 = 和原来一样多）；背景音乐文件、音乐音量（0–1，默认 0.5）、「我有这段音乐的使用授权」勾选框 |

模板决定的是**看得见的内容和节奏安排**（片头片尾、封面、字幕、调色、水印、AI 标识、重新分集、背景音乐）；
输出规格和细微处理参数不在模板里（见 8.4）。

几条硬性限制（界面会直接拦下或标红）：

- 用了背景音乐就**必须**勾上「我有这段音乐的使用授权」，否则保存不了；
- 勾了 AI 标识时，剧名水印**不能**放在右下角（那里留给 AI 标识）；
- AI 生成合成服务提供者只能用字母、数字和常见英文符号（不能有空格、中文、引号、反斜杠）；
- 「重新分集」和「烧字幕」不能同时开：重新分集后原字幕的时间对不上；
- 重新分集的集数最多是原集数的 10 倍。

### 8.4 哪些东西改不了

- **输出规格**由服务端配方给出，页面上只是显示：1080×1920 竖屏、30 帧、H.264 + AAC、
  视频码率不超过 5000 kbps、单集时长上限 15 分钟（比例不一致时等比缩放加黑边）；
- **细微处理参数**（颗粒、轻微放大裁边、亮度饱和度色相微调、变速变调、首尾裁几帧）的数值同样来自配方，
  你只能选档位，不能逐项调；
- **画质下限**也来自配方。

### 8.5 需要联网的地方

- 「预览计划」只在本机核对，不联网、不扣次数。
- 「开始生成」要向服务端申请一份处理配方，并**立即用掉**：配方只能用一次，
  换档位、改模板就得删掉这次的版本目录重新申请。万一配方用掉之后任务没能排队（极少见：磁盘写不进去），
  会明确提示「配方已经用掉，请稍后重新申请」，这次不会生成任何文件。
- 任务中途暂停或终止**不用重新申请**：点「继续」会用本机保存的配方原文接着做。失败的任务也能「继续」；
  但如果失败原因是文件层面的（源文件在申请后被改动、背景音乐换了、配方校验不过），继续会再失败，
  那就得恢复文件，或者删掉这次的版本目录整个重做——**重做要重新申请配方**（配方一次性，服务端也有限流）。
- **续跑不用联网**：用本机保存的配方原文重新校验，参数和种子不变，产出的文件和第一次完全相同。
- 配方绑定的是**申请那一刻的那批文件**：申请时按内容算过哈希，每集开工前还会重算一次，
  分集被换掉或改过就拒绝处理这一集。

### 8.6 画质检测

每一集都在同一次编码里分出一路「只做几何处理」（缩放、补边、裁首尾帧、变速）的画面作参考，
和「做完颗粒与调色之后」的画面对比，算出 SSIM 与 PSNR——字幕、水印、AI 标识是有意加的内容，
不算画质损失。低于配方下限的那一集判为**失败、不交付**，这一集的输出文件会被删掉，不会留下半成品；
收尾时只把通过检测的集写进 `版本说明.json`，并在里面记下档位、配方编号与种子、输出规格、
画质下限、每集的画质分数、实际使用的编码器和输出文件的校验值，方便事后复核。

### 8.7 AI 标识

勾了「本剧视频含 AI 生成内容」之后：

- 成片**开头 3 秒**在右下角显示「人工智能生成合成」，之后同一位置常驻「AI生成」；
- 文件元数据里同时写入隐式标识（生成合成服务提供者、内容制作编号）；
- 剧名水印不能放在右下角；
- 画面上要写字（水印、AI 标识、封面文字）就需要**中文字体**：应用会先找系统字体，
  找不到时会挡下生成并提示去「设置 → 本机环境」指定字体文件。

## 9. 模块四：工具箱

工具箱顶部有一张「该用哪个工具？」引导卡，先按它选工具：

| 你的目标 | 用哪个 |
| --- | --- |
| 只想先看看要改什么 | 视频转码 → **转码建议**（只出建议，不动文件） |
| 只是码率不达标 | **码率修复**（会就地重编码，**替换原文件**） |
| 要改时长、顺序或分集数 | 视频转码 → **执行转码**（输出到新目录） |
| 文件名不统一 | **批量改名**（集号解析依赖文件名） |

工具卡片默认折叠，点标题展开。除改名与码率修复外，其余工具都会**另写新目录**，不动原素材。

### 9.1 批量改名

- 「预览改名计划」：列出每集的当前文件名 → 目标文件名（规则：`剧名 - 第NN集`）与状态
  （`待改名` / `已合规`）；解析不出集号的文件会单列为「无法解析、保持不动」。
- 预览是**必须的第一步**：没有计划，「应用改名」是灰的。
- 目标名冲突或重复时**整体拒绝**，不会改到一半。
- 应用成功后旧计划立即作废，再点需要重新预览。改名后建议回「剧目库」重新扫描并检查。

### 9.2 码率修复

- 先设「码率安全线（Mbps）」（默认 4）→ 点「检测码率」，逐集给出实测码率与
  `达标 / 低于安全线 / 探测不到码率`；有低于安全线的分集时「修复不达标分集」才会亮起。
- 点修复会先弹出**二次确认**，写清「即将重编码 N 集、原文件会被替换（视频与音频都会重新编码）、
  没有备份、不能撤销」，并列出前几个文件名。确认后才开始。
- 修复走「临时文件 + 原子替换」，但**仍然没有备份**。重要素材请先自行备份，或先在副本上试一集。
- 结束后给出每集「原码率 → 新码率」，失败项单列原因。结果已变化，需重新「检测码率」。

### 9.3 视频转码

**转码建议与批量规范化**（只建议，不自动执行）

- 填目标容器、码率上限（Mbps）、最大宽/高（0 表示不限）→「生成转码建议」。
- 输出：共几集、需转码几集、已合规几集；需转码的逐集给出**原因**；下面可展开查看批量 `ffmpeg` 脚本预览。
- 它给出的输出目录是预览值（剧目目录下的 `规范化/`），这一步不会写任何文件。

**执行转码**（会真的跑，耗时较长）

- 「智能微调」每集裁掉开头 1~3 帧（每次不同）；「分集重组」按场景切点把全剧重新分集，
  可填「目标集数」（留空保持原集数）。
- 输出目录留空时，先看「设置 → 默认输出目录」：设了就写到「该目录 / 剧名 / 微调输出（或 重组输出）」，
  没设才写到「剧目目录/微调输出」或「剧目目录/重组输出」；填了则写到你指定的目录。
- **输出目录不允许等于素材目录**：那种情况会覆盖原素材，界面会在输入框下直接标红拦下，
  后端在真正执行前也会再拦一次。全剧重编码，请预留时间。

### 9.4 报审包差异对比

读两份报审包的 `manifest.json`，列出改稿前后的**新增 / 移除 / 修改**文件，并给出两份报审包的
生成时间对照。它只读清单，不读素材内容，也不改动任何文件。

### 9.5 平台材料要求（示例档案）

- 内置档案是**学习示例**，不是任何平台的官方规范。
- 「对照当前剧目」会逐集对照时长、画幅、码率、编码与必需材料，输出「N 项阻断 / N 项警告」，
  或「无阻断项」。绿色=无阻断、黄色=有警告、红色=有阻断。

### 9.6 剪映草稿

- 「导出草稿」：把分集顺序与时长写成剪映草稿目录（留空写到剧目目录），结束后回填实际目录。
- 「读回草稿」：选择草稿目录，列出片段顺序、时间线起点与时长，用来和素材核对。
- 剪映草稿格式随版本变化，这只是**交接与核对**用途。

### 9.7 字幕 / 角标擦除（实验功能）

- 只处理**自有素材**的硬字幕与角标；本功能不提供任何绕过版权保护或去除他人作品标识的能力。
- 使用顺序：选输入视频 → 选输出视频 → 填区域（`x,y,w,h`，多个用分号分隔）→
  （可选）检测后端/修复后端与高级参数 → 「预览命令」看将要执行的命令 →
  「执行擦除」。
- **输入与输出不能是同一个文件**：界面会就地拦下，后端在执行前也会再拦一次，避免边读边写毁掉源素材。
- 执行期间进度条是**确定进度**：分「定位字幕区域」「逐片段修复画面」两段，显示到第几段与已完成多少帧。
- 结束后回显结论与退出码（`0` 通过 / `3` 需人工抽查 / `2` 校验失败），以及残留峰值、
  结构相似度最低值和处理日志路径。
- 「检测工具状态」用于确认擦除工具是否可用（缺少模型 worker 时会说明）。

## 10. 模块五：设置

### 检查规则与路径

- 可改：最少集数、单集时长下限/上限（秒）、码率上限（Mbps）、是否对横屏分集给警告。
- 可改：默认输出目录（`ffprobe` 路径不在这里，见下一节「本机环境」）。
  它是**产物的根目录**：留空时产物写在各自剧目目录内；填了则按「该目录 / 剧名 / 产物名」落盘，
  多部剧各占一个子目录、不会互相顶掉。生成报审包、智能微调/分集重组、处理版本都读这个值，
  各页自己的「输出目录」输入框只是**本次运行**的临时覆盖。
- **保存后才生效**：探测与生成都读「已保存的设置」；改了没保存时，标题右侧会显示
  `有改动未保存` 徽标。表单里的临时改动不会偷偷生效。
- 「恢复默认」只回填表单为内置默认值，仍然要点「保存设置」才生效。
- 「生成报审包」页里的同名输入是**本次运行覆盖**，不改变设置。
- 素材根目录不在这一页填：扫描成功后应用会自动记住，下次启动时「剧目库」的目录框会直接回填。
- 设置只写入本机配置文件，页面底部会显示它的**实际路径**（应用配置目录下的 `settings.json`）。

### 本机环境

- 逐项列出 `ffmpeg` / `ffprobe` / `python` 的「已找到 / 未找到」与版本说明。
- **一键配置运行环境**：自动下载安装 `ffmpeg` / `ffprobe`（约 25 MB，需要联网），完成后把路径写入设置
  并重新检测；下载期间按钮会保持禁用，网络慢时可能要等几分钟。**这个按钮只在 macOS 上出现**；
  Windows / Linux 上同一位置显示的是手动安装指引（`winget install Gyan.FFmpeg` /
  `sudo apt install ffmpeg`），装好后再用下面的「ffprobe 路径」指定位置。
- **重新检测**：立刻再跑一遍环境探测。
- **ffprobe 路径（高级）**：手动指定可执行文件位置；留空则由应用按「设置里的路径 → 安装目录 → 系统
  `PATH`」自动查找。改完保存设置会自动重新检测。
- **中文字体文件**（「处理版本」那一组）：水印、AI 标识、封面文字要用的字体，可从 `ttf` / `otf` / `ttc`
  里选。**留空时**自动找系统字体（macOS 苹方、Windows 微软雅黑、Linux 上的 Noto CJK 等）；
  指定的文件不存在时会直接报错，不会偷偷换成别的字体。生成处理版本前若提示「没找到中文字体」，就填这一项。
- **只用软件编码**（「处理版本」那一组）：默认不勾——有可用的显卡编码就用（更快）；
  某一集显卡编码失败时会自动改用软件编码重做，任务列表和版本说明里都会写明。
  **什么时候要勾**：显卡编码在本机跑起来不稳、画面异常或反复退回软件编码时，勾上就一律用软件编码，
  省掉每次失败的尝试。改动保存后，对之后开始或继续的任务生效。

### 关于

显示版本号，并说明素材和报审包只保存在本机、不上传；账号、使用权和设备绑定记录保存在服务端。

## 11. 任务

侧栏底部的「任务」是处理版本的生成队列。同一时间只跑一个任务（视频编码本来就吃满 CPU/GPU，
并行只会都变慢），后面的任务依次排队。入口上会显示还没结束的任务数，卡片里能看到进度条、
每集的状态和说明（画质分数、实际用的编码器），也能直接「打开目录」。

### 六种状态

| 状态 | 含义 |
| --- | --- |
| 排队中 | 已提交，等前面的任务做完 |
| 运行中 | 正在跑，卡片里会显示「正在处理 第NN集.mp4」 |
| 已暂停 | 你点了暂停，或应用重启后没做完的任务统一落到这个状态 |
| 已终止 | 你点了终止，或重启前就被终止了 |
| 完成 | 全部步骤做完 |
| 失败 | 某一步出错（画质低于下限、源文件被改动、ffmpeg 报错等），卡片上会写清原因和停在哪一集 |

### 三个按钮

- **暂停**：排队中的任务立刻停下；运行中的任务是「**当前这一集做完再停**」，
  点下去会提示「会在当前这一集做完后暂停」，不会打断正在编码的那一集。
- **终止**：**立刻**结束正在跑的 `ffmpeg` 进程，并删掉这一集的半成品；已经做完的集保留。
  会先弹一次确认。
- **继续**：已暂停、已终止、失败的任务都能继续。继续时会核对已完成各集的产物：
  **产物还在、内容没被改过的集直接跳过**，产物缺失或哈希对不上的集重做。

看任务、暂停、终止这三件事任何时候都能做，不要求账号还有有效使用权——即使授权恰好到期了，
也能把正在跑的编码停下来。

### 重启之后

关掉应用再打开，「任务」里没做完的任务会停在**已暂停**——不会在你不知情时自动开工，
要手动点「继续」才接着跑。任务进度、每集的产物记录都保存在本机，重启不丢。

## 12. 常见问题与排错

| 现象 | 原因与处理 |
| --- | --- |
| 顶部横幅提示「运行环境未就绪」 | macOS：点横幅上的「一键配置运行环境」自动下载安装（约 25 MB，需要联网）。Windows / Linux：按横幅给出的命令手动安装 FFmpeg（含 `ffprobe`）并确保在 `PATH` 中 |
| 右上角提示「缺少 ffmpeg / ffprobe」 | 点标签或顶部横幅；或在「设置 → 本机环境」里指定 `ffprobe` 路径后保存 |
| 一键配置后仍提示未就绪 | 应用装完会自动重测；若仍缺，检查是否杀软拦截下载，或手动在「设置 → 本机环境」填 `ffprobe` 路径并保存 |
| 找不到「一键配置运行环境」按钮 | 这是刻意隐藏的：该功能只有 macOS 有可用下载源，其他平台请按横幅/设置页给出的命令手动安装 |
| 「探测并检查」失败并提到 ffprobe/启动/PATH | 同上；错误信息里会点名本机缺的是哪个工具 |
| 「请先选择剧集素材根目录」 | 先填/选根目录再点扫描 |
| 提示「报审包目录已存在」 | 换一个输出目录，或先把旧报审包移走/改名（不会覆盖已有材料） |
| 提示「这一步需要联网」 | 生成报审包、开始生成处理版本都必须联网（生成报审包执行前还会联网刷新一次授权）；断网时先连上网再点 |
| 提示「这个账号还没有使用权」/「使用权已到期」 | 账号没兑换过卡密或使用权已到期；去「授权卡密」页兑换或续期后再生成 |
| 生成时报「没有有效的使用权」 | 执行前本机授权是好的，但服务端复核时使用权已不生效（例如刚在别处到期）；兑换或续期后重试 |
| 提示「找不到本机文件 …」或「… 在提交后被改动或调换过」 | 生成期间把分集移走、改名、改内容或两集对调了。文件放回原位、内容恢复后**重新生成**；本次不会留下半个目录 |
| 包里的 PDF 上有「样章 · 未签署 · 无法律效力」和斜向水印 | 这是**占位章**，不是盖章文件。正式报审前要换成盖章版本 |
| 生成时报「服务暂时不可用」 | 服务端要么找不到报审包生成工具，要么签章服务不可用。稍后重试；持续出现请联系管理员 |
| 「输出目录不能是素材目录」 | 转码输出不能写回素材目录；清空让应用写到剧目目录下的子目录，或另选目录 |
| 「输出视频不能与输入视频相同」 | 擦除的输入输出必须不同，改输出文件名 |
| 改名按钮是灰的 | 需要先「预览改名计划」，且已有 `待改名` 项、当前没有别的任务在跑 |
| 提示「已经有任务在进行」 | 上一个耗时操作还没结束，等进度条走完再点 |
| 某个按钮点了没反应 | 长任务开始后所有耗时按钮会统一置灰，这是防止重复执行，不是卡住 |
| 检查结果长期是 `尚未探测` | 只扫了目录没点「探测并检查」，或探测失败（看失败原因那一行） |
| 码率修复后仍提示低于安全线 | 修复结果已变化，需要重新「检测码率」；个别失败项会在结果里列出原因 |
| 「探测不到码率」 | 该文件本身没有可用码率信息，需要人工确认 |
| 处理版本提示「这部剧已经有处理版本」 | 一部剧只保留一套处理版本。想重做要先删掉旧的版本目录，再重新「预览计划」并重新申请配方 |
| 处理版本提示「画质低于下限…这一集不交付」 | 这一集没通过配方里的画质下限，输出文件已删掉。可以先「继续」再试一次；要换更轻的档位，得先删掉这次的版本目录再重新开始 |
| 处理版本提示「本机没找到中文字体」 | 画面上要写字（水印、AI 标识或封面文字）但找不到字体。去「设置 → 本机环境」的「中文字体文件」里指定一个 `.ttf` / `.otf` / `.ttc` 并保存 |
| 处理版本提示「权属材料文件的内容变了」 | 声明过的证书 / 授权书被改过或移走了，回「处理版本」页重新声明 |
| 处理版本提示「源文件和开始生成时不一样了」 | 分集在申请配方之后被改动过。恢复原文件后点「继续」；换素材只能删掉这次的版本目录重做（重做要重新申请配方） |
| 任务一直停在「已暂停」 | 应用重启过，没做完的任务一律先停下，点「继续」就会接着跑 |

如果应用无响应：先等进度条结束（重编码与擦除可能数分钟）；确认无任务后再操作。

## 13. 已知限制

- 界面**不做**素材的剪切/合成，转码与重编码只做规范化与分集重组；时长/内容层面的修改请回剪辑软件。
- 「平台材料要求」是内置示例档案，不是官方规范；请替换为平台方最新要求后再使用。
- 擦除是实验能力：小掩码（角标/窄字幕条）精度最高，大面积或复杂背景需要人工抽查；
  缺少模型 worker 时部分后端不可用。
- 擦除进度的粒度是**每 30 帧一条**（管线按片段上报），不是逐帧；进度条会成段往前走。
  另外阶段内还没拿到总量时（素材未写 `nb_frames` 等）会先按不确定进度显示，拿到帧数后自动切换。
- 剪映草稿格式随剪映版本变化，读回功能可能受版本影响。
- 报审包生成不做增量更新：目标目录已存在就拒绝，需要你显式换目录。
- 生成报审包和开始生成处理版本都**必须联网**，且账号要有有效使用权；断网时其他本地功能照常可用，
  只有这两步会被挡下（处理版本的暂停后续跑不用联网）。
- 服务端签发的成本配置表与内容权属声明现在是**占位章**（未签署、无法律效力），
  不能直接拿去报审；DramaDossier 只提供占位章这一种出包方式，盖章版本要在这一步之后另外处理。
- 检查规则可配置，但**规则再严也代替不了人工复核**：`材料可用` 只表示无失败项。
- **一部剧只保留一套处理版本**：版本目录已存在时「开始生成」会被挡下，提示「这部剧已经有处理版本」。
  想重做（换档位、改模板、换素材）要先自己删掉旧的版本目录再重新预览、重新申请配方。
- 处理版本**不保证不被平台降权**：它按服务端配方做细微处理，但平台的判定规则不公开、随时可能变，
  要不要用、用哪一档请自己判断。
- **硬件编码在本机 Linux 上没验证过**：Windows / macOS 上的显卡编码由平台信号常开、再由
  `ffmpeg -encoders` 列表与单帧实测把关；Linux 上要求对应的设备节点（`/dev/nvidia*`、
  `/dev/dri/renderD*`、`/dev/video*`）在，才可能选中 NVENC / VAAPI / V4L2。
  本项目的 Linux 构建机上 `h264_vaapi` 就是初始化失败、退回软件编码的。
  硬件编码失败会自动改用软件编码，也可以在「设置 → 本机环境」里直接勾「只用软件编码」。

## 14. 隐私与合规边界

- 应用访问网络只有这几种情况：① 账号登录、授权刷新、生成报审包、开始生成处理版本时申请与消费处理配方
  （联网请求服务端）；② 你**主动点击**「一键配置运行环境」时下载官方 ffmpeg 压缩包；
  ③ 启动本机 `ffprobe` / `ffmpeg` 等外部进程本身不联网。
  **素材文件始终不上传**：生成报审包时只把文件名、大小、SHA-256 和探测规格发给服务端；
  申请处理配方时只发任务哈希（由分集文件哈希、模板哈希、权属材料哈希和档位算出来）、
  档位和固定规格名 `universal`，分集视频、封面、简介都留在本机。
- 设置里填写的公司、联系方式只出现在「生成报审包」页的表单里（**不写入本机配置文件**），
  生成时随成本表单发给服务端用于生成成本配置表；服务端只存报审包的元数据
  （账号、机器码、生成时间、签章方式、集数、清单哈希），不保存文档内容，审计日志里也不记剧名、
  公司名、联系方式原文。这些内容会照你填写的样子写进本机报审包（成本表、权属声明）。
- 剧备只整理**使用者提供的真实材料**，固定包含内容权属声明模板，但**不伪造**签名、印章或时间戳；
  `manifest.json` 是完整性清单，不是官方审核回执。占位章会明确标出「未签署、无法律效力」。
- 擦除功能仅限自有素材；不提供 DRM 绕过，也不处理他人作品的版权标识。
- 处理版本用到的权属材料**只在本机留记录**（路径 + 校验值，写进剧目目录的 `.dossier/rights.json`
  和本机处理台账），不核验真伪、也不上传材料内容；背景音乐要不要用、有没有授权由你勾选并负责。
- 本项目定位为技术学习与交流的示例，文中的报审格式、平台要求与发布流程都不构成合规或法律意见。

## 附录 A：报审包目录结构

```text
报审包/
├── 01_剧集信息/
│   ├── 剧名.txt
│   └── 简介.txt
├── 02_封面海报/
│   └── 封面.jpg
├── 03_分集清单/
│   └── 分集清单.csv
├── 04_成本配置表/
│   ├── 成本配置表.md
│   └── 成本配置表_未签署.pdf      # 占位章，未签署、无法律效力
├── 05_权属声明/
│   ├── 内容权属声明.txt
│   └── 内容权属声明_未签署.pdf    # 占位章，未签署、无法律效力
├── 06_分集视频/        # 仅在勾选「复制分集视频进报审包」时生成
│   └── 第01集.mp4
├── manifest.json
└── manifest.sig
```

`manifest.json` 记录 `schema`（现在是 `drama-dossier/package@2`）、报审包 ID、剧名、生成时间、
账号与机器码、是否 AI 辅助、是否复制分集、签章方式与两份未签署文档，以及包内每个文件的
`path` / `sizeBytes` / `sha256` / `source`；不复制进包的分集登记在同级的 `references` 里。
`manifest.sig` 是服务端对 `manifest.json` 原始字节的 Ed25519 签名，组装前先验签。
完整字段见 [`MATERIAL_SPEC.md`](MATERIAL_SPEC.md)。

## 1. 这是什么

剧备是一个**本地优先**的桌面应用：素材、检查报告、生成结果全部留在你自己的电脑上，不注册账号、
不上传素材、不做云端同步。

它帮你把这几件重复劳动自动化：

1. 按约定扫描本机的剧集素材目录，认出「一部剧 = 一个子目录」；
2. 调用本机 `ffprobe` 读取每一集的时长、分辨率、编码、帧率、码率；
3. 按可解释的规则给出检查结论（哪些缺失、哪些需要人工确认）；
4. 生成编号清晰的报审包目录 + 本地完整性清单 `manifest.json`；
5. 附带一个后期工具箱（改名、码率修复、转码、差异对比、草稿交接、字幕/角标擦除）。

**它不做什么**：不代你填真实信息、不伪造签名/印章/时间戳、不替代平台审核、不绕过任何版权保护。
规则里的阈值与「平台档案」都是**学习示例**，接入真实业务前必须换成平台方最新规范。

## 2. 装好之后先做一次环境自检

剧备自己不含视频工具，需要本机有 **FFmpeg（必须包含 `ffprobe`）**。可以自己装，也可以让应用帮你装。

- 启动后，如果缺少工具，窗口**顶部**会出现一条**运行环境横幅**，上面直接带「一键配置运行环境」按钮：
  点一下会自动下载安装 `ffmpeg` / `ffprobe`（约 25 MB，需要联网），装好后路径自动写入设置并重新检测；
  环境就绪后横幅自动隐藏，不再占版面。**不用等你点了按钮才发现跑不通。**
  - 该按钮**目前仅在 macOS 上出现**（下载 evermeet.cx 的官方构建，会用到系统自带的 `curl` 与 `unzip`）。
    Windows / Linux 上**不会**显示这个按钮，横幅与「设置 → 本机环境」会改成给出对应平台的手动安装命令：
    Windows 用 `winget install Gyan.FFmpeg`（或到 gyan.dev 下载后把 `bin` 加入 `PATH`），
    Linux 用 `sudo apt install ffmpeg` / `sudo dnf install ffmpeg`。
  - Apple 芯片（Apple Silicon）首次使用若提示 CPU 架构不匹配，请先在终端执行
    `softwareupdate --install-rosetta --agree-to-license` 安装 Rosetta 2，再重新点击一键配置。
- 窗口右上角另有一个**常驻环境标签**，随时反映状态：
  - `本机环境就绪`（绿）：可以正常扫描、探测、生成；
  - `缺少 ffmpeg` / `缺少 ffprobe`（红）：还没找到，点一下跳到「设置 → 本机环境」看详情；
  - `环境异常：ffmpeg / ffprobe`（黄）：找到了但不可用（例如路径指向了别的程序），同样点标签查看。
- 「设置 → 本机环境」里除了「一键配置运行环境」，还有「重新检测」，以及一个高级项
  「ffprobe 路径」（例如 `/opt/homebrew/bin/ffprobe`、`C:\ffmpeg\bin\ffprobe.exe`）。
  **留空时**应用按「设置里的路径 → 安装目录 → 系统 `PATH`」的顺序自动查找。

缺 FFmpeg 时仍然能做的事：**扫描剧目**（只读文件名与体积）。会失败的事：**探测并检查**、
生成报审包、码率修复、执行转码。注意「一键配置运行环境」是应用里**唯一**会联网的动作，
且只下载官方的 ffmpeg 压缩包。

## 3. 界面总览

界面是一列左侧导航 + 四块工作区，任何时刻只显示一块：

| 区域 | 作用 |
| --- | --- |
| 剧目库 | 选素材根目录 → 扫描 → 点选一部剧 → 探测并检查 |
| 生成报审包 | 填写出品方、投资额等信息并生成报审包 |
| 工具箱 | 改名、码率修复、转码、报审包对比、平台档案、剪映草稿、擦除 |
| 设置 | 检查规则阈值、默认路径、本机环境、关于 |

界面顶部还有这几样东西：

- **运行环境横幅**：只在缺少 `ffmpeg` / `ffprobe` 时出现，装好即隐藏。macOS 上带「一键配置运行环境」
  入口，其他平台改为直接给出该平台的手动安装命令；
- **常驻环境标签**（右上角）：随时显示「本机环境就绪」或缺哪个工具，点一下跳到「设置 → 本机环境」；
- **当前剧目**标签：提醒你现在所有操作都作用在哪一部剧上；
- **进度条**：所有耗时操作都会显示。逐集探测能算出总量时是**确定进度**（`正在探测分集 3/12：第03集.mp4`），
  转码与码率修复按「第 3/8 集」这类单元显示确定进度；擦除按「第几段 + 已完成多少帧」显示确定进度
  （`擦除中 · 逐片段修复画面（第 2/2 段）：已完成 1234/5000 帧`）。
  真的算不出总量时才退回**不确定进度 + 已用秒数**；
- **提示条（Toast）**：失败用红色并统一带「出错了：」前缀，停留时间也更长（9 秒，成功为 4.5 秒）。
  除了颜色还有文字前缀，截图或投屏也能分辨成功与失败。
  路径、权限、运行环境这类**能指出下一步**的错误会直接带一个按钮（「打开设置」/「重新检测」/
  「去设置环境」），点了就跳过去，不用自己翻页找。

**长任务只允许一个**：只要有任务在跑（扫描、探测、生成、改名、码率检测/修复、转码、平台对照、
草稿读写、擦除），所有耗时按钮都会自动置灰，避免重复点击把同一件事跑两遍。想再点会提示
「已经有任务在进行」。

## 4. 五分钟上手

1. 打开应用 → 左侧「剧目库」。首次进入时中间会有一份**三步引导**（选择目录 → 扫描剧目 →
   点选剧目并探测），每完成一步前面的圆圈会打勾，也可以直接点引导里的按钮走完，不必自己找入口。
2. 在「素材根目录」里输入或点「选择」挑一个目录（里面每个子目录 = 一部剧）。
   扫描成功后这个路径会**自动记住**，下次启动直接回填。
3. 点「扫描剧目」，左侧会列出找到的剧目与集数、总体积。
4. 点选一部剧 → 点右上角「探测并检查」，等待进度条走完。
5. 看「检查结果」（通过 / 需确认 / 不通过）和「分集」表，按提示补齐缺失材料。
6. 切到「生成报审包」，填出品方等信息 → 点「生成材料包」。
7. 生成完可以点结果里的「打开目录」直接跳到报审包，或「复制路径」发给同事。

## 5. 素材怎么准备

推荐的目录结构（根目录下每个子目录是一部剧）：

```text
素材根目录/
└── 示例短剧/
    ├── 第01集.mp4
    ├── 第02集.mp4
    ├── 封面.jpg
    └── 简介.txt
```

- 视频扩展名：`mp4`、`mov`、`mkv`、`flv`、`ts`、`m4v`、`webm`；
  图片：`jpg`、`jpeg`、`png`、`webp`；文本：`txt`、`md`。
- 剧目目录内部的**一层子目录**也会被扫描。
- 集号解析优先级：① `第12集` / `第12话` / `第12回` → ② 词边界的 `E12` / `e03` → ③ 主干里的独立数字（`show_12`）。
  解析不出集号的文件会被列入「无法解析」并保持不动（不会乱改名）。
- 封面建议 `封面.jpg`，简介建议 `简介.txt`，不少于 30 字，写清题材、主要人物、受众定位。

> 小贴士：文件名不统一时，先去**工具箱 → 批量改名**把它统一成「剧名 - 第NN集」，
> 再做探测与生成——集号解析依赖文件名。

## 6. 模块一：剧目库

### 扫描剧目

- 输入/选择根目录 → 「扫描剧目」。找不到子目录时会显示「未找到剧目子目录。」。
- 左侧剧目条目显示：剧名、集数、素材总体积。
- **切换剧目或重新扫描会作废工具箱里上一部剧的计划与结论**，防止拿旧计划点执行。

### 探测并检查

点「探测并检查」后逐集读取规格，结果分两块：

- **检查结果**：每条给出「项目 + 状态 + 说明」。状态含义：
  `通过` / `需确认`（警告，需要人工判断）/ `不通过`（缺失等失败项）/ `尚未探测`。
  右上角徽标是总览：`材料可用`（无失败项）或 `有缺失项`。
- **分集**表：集号、文件名、时长、`宽×高`、状态。探测失败的那一行直接显示失败原因。

`材料可用` 只代表**没有失败项**，警告项仍然要人工确认。

## 7. 模块二：生成报审包

上半部分是「本次运行覆盖」，只影响这一次；长期默认值在「设置」里。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 输出目录（本次覆盖） | 否 | 留空 = 按「设置 → 默认输出目录 / 剧名 / 报审包」落盘，设置也为空时才写到「剧目目录/报审包」。填了就生成到你指定的目录 |
| 出品 / 公司 | 否 | 写进报审包的成本表与权属声明；请填**真实**信息 |
| 投资总额（万元） | 否 | 必须是不小于 0 的数字，格式错误会在输入框下就地标红 |
| 演员成本占比（%） | 否 | 必须在 0–100 之间 |
| 联系方式 | 否 | 仅写入本地报审包 |
| 复制分集视频进报审包 | 否 | 勾选后会额外生成 `06_分集视频/`（最耗时的一步，进度条会说明） |
| 使用了 AI 辅助生成 | 否 | 如实勾选，会记进 `manifest.json` 的 `aiGenerated` |

这一页**不再单填 ffprobe 路径**：读取规格用的 `ffprobe` 统一取「设置 → 本机环境」里的配置
（留空则自动查找）。

点「生成材料包」后：会**先重新探测一遍**（避免用过期规格），再写报审包，最后结果里给出位置、
文件数与总大小，并提供「打开目录 / 复制路径」。

几点须知：

- 目标目录**已存在**时会直接拒绝，提示「报审包目录已存在」，不会覆盖已有材料。
  这时结果区会直接给出旧包位置，可以点「打开目录」先确认；提示条上还有「换个输出目录」按钮，
  点一下就能重新挑目录再生成（旧目录始终不会被改动）。
- 生成失败时结果区用红色展示，不会与成功色混淆。
- 报审包结构与 `manifest.json` 字段见[附录 A](#附录-a报审包目录结构)与 [`MATERIAL_SPEC.md`](MATERIAL_SPEC.md)。

## 8. 模块三：工具箱

工具箱顶部有一张「该用哪个工具？」引导卡，先按它选工具：

| 你的目标 | 用哪个 |
| --- | --- |
| 只想先看看要改什么 | 视频转码 → **转码建议**（只出建议，不动文件） |
| 只是码率不达标 | **码率修复**（会就地重编码，**替换原文件**） |
| 要改时长、顺序或分集数 | 视频转码 → **执行转码**（输出到新目录） |
| 文件名不统一 | **批量改名**（集号解析依赖文件名） |

工具卡片默认折叠，点标题展开。除改名与码率修复外，其余工具都会**另写新目录**，不动原素材。

### 8.1 批量改名

- 「预览改名计划」：列出每集的当前文件名 → 目标文件名（规则：`剧名 - 第NN集`）与状态
  （`待改名` / `已合规`）；解析不出集号的文件会单列为「无法解析、保持不动」。
- 预览是**必须的第一步**：没有计划，「应用改名」是灰的。
- 目标名冲突或重复时**整体拒绝**，不会改到一半。
- 应用成功后旧计划立即作废，再点需要重新预览。改名后建议回「剧目库」重新扫描并检查。

### 8.2 码率修复

- 先设「码率安全线（Mbps）」（默认 4）→ 点「检测码率」，逐集给出实测码率与
  `达标 / 低于安全线 / 探测不到码率`；有低于安全线的分集时「修复不达标分集」才会亮起。
- 点修复会先弹出**二次确认**，写清「即将重编码 N 集、原文件会被替换（视频与音频都会重新编码）、
  没有备份、不能撤销」，并列出前几个文件名。确认后才开始。
- 修复走「临时文件 + 原子替换」，但**仍然没有备份**。重要素材请先自行备份，或先在副本上试一集。
- 结束后给出每集「原码率 → 新码率」，失败项单列原因。结果已变化，需重新「检测码率」。

### 8.3 视频转码

**转码建议与批量规范化**（只建议，不自动执行）

- 填目标容器、码率上限（Mbps）、最大宽/高（0 表示不限）→「生成转码建议」。
- 输出：共几集、需转码几集、已合规几集；需转码的逐集给出**原因**；下面可展开查看批量 `ffmpeg` 脚本预览。
- 它给出的输出目录是预览值（剧目目录下的 `规范化/`），这一步不会写任何文件。

**执行转码**（会真的跑，耗时较长）

- 「深度处理」把两件事串起来：先按场景切点把全剧重新分集（重组），再对每个新集裁掉开头
  1~3 帧（微帧），最后统一编码到新目录。
- 深度处理还会**并行启动材料线程**：按「设置 → 目录与引擎 → 内容模型」里的抽样集数，用
  ASR 识别对白、OCR 识别画面文字，再让配置的 LLM 生成剧名/简介/分镜概要，并生成海报与
  4 张过程图。材料失败只记警告，不会回滚已经完成的成片编码。
- 推荐本机安装 whisper.cpp（显式填写模型文件）与 Tesseract（含 `chi_sim` 语言包）；
  应用不会自动下载大模型，未配置时材料线程会跳过并在结果里说明原因。
- 输出目录留空时，先看「设置 → 默认输出目录」：设了就写到「该目录 / 剧名 / 深度处理」，
  没设才写到「剧目目录/深度处理」；也可以直接在「设置 → 生成设置」里指定深度处理输出目录。
- **输出目录不允许等于素材目录**：那种情况会覆盖原素材，界面会在输入框下直接标红拦下，
  后端在真正执行前也会再拦一次。全剧重编码，请预留时间。

### 8.4 报审包差异对比

读两份报审包的 `manifest.json`，列出改稿前后的**新增 / 移除 / 修改**文件，并给出两份报审包的
生成时间对照。它只读清单，不读素材内容，也不改动任何文件。

### 8.5 平台材料要求（示例档案）

- 内置档案是**学习示例**，不是任何平台的官方规范。
- 「对照当前剧目」会逐集对照时长、画幅、码率、编码与必需材料，输出「N 项阻断 / N 项警告」，
  或「无阻断项」。绿色=无阻断、黄色=有警告、红色=有阻断。

### 8.6 剪映草稿

- 「导出草稿」：把分集顺序与时长写成剪映草稿目录（留空写到剧目目录），结束后回填实际目录。
- 「读回草稿」：选择草稿目录，列出片段顺序、时间线起点与时长，用来和素材核对。
- 剪映草稿格式随版本变化，这只是**交接与核对**用途。

### 8.7 字幕 / 角标擦除（实验功能）

- 只处理**自有素材**的硬字幕与角标；本功能不提供任何绕过版权保护或去除他人作品标识的能力。
- 使用顺序：选输入视频 → 选输出视频 → 填区域（`x,y,w,h`，多个用分号分隔）→
  （可选）检测后端/修复后端与高级参数 → 「预览命令」看将要执行的命令 →
  「执行擦除」。
- **输入与输出不能是同一个文件**：界面会就地拦下，后端在执行前也会再拦一次，避免边读边写毁掉源素材。
- 执行期间进度条是**确定进度**：分「定位字幕区域」「逐片段修复画面」两段，显示到第几段与已完成多少帧。
- 结束后回显结论与退出码（`0` 通过 / `3` 需人工抽查 / `2` 校验失败），以及残留峰值、
  结构相似度最低值和处理日志路径。
- 「检测工具状态」用于确认擦除工具是否可用（缺少模型 worker 时会说明）。

## 9. 模块四：设置

### 检查规则与路径

- 可改：最少集数、单集时长下限/上限（秒）、码率上限（Mbps）、是否对横屏分集给警告。
- 可改：默认输出目录（`ffprobe` 路径不在这里，见下一节「本机环境」）。
  它是**产物的根目录**：留空时产物写在各自剧目目录内；填了则按「该目录 / 剧名 / 产物名」落盘，
  多部剧各占一个子目录、不会互相顶掉。生成报审包、智能微调/分集重组都读这个值，
  各页自己的「输出目录」输入框只是**本次运行**的临时覆盖。
- **保存后才生效**：探测与生成都读「已保存的设置」；改了没保存时，标题右侧会显示
  `有改动未保存` 徽标。表单里的临时改动不会偷偷生效。
- 「恢复默认」只回填表单为内置默认值，仍然要点「保存设置」才生效。
- 「生成报审包」页里的同名输入是**本次运行覆盖**，不改变设置。
- 素材根目录不在这一页填：扫描成功后应用会自动记住，下次启动时「剧目库」的目录框会直接回填。
- 设置只写入本机配置文件，页面底部会显示它的**实际路径**（应用配置目录下的 `settings.json`）。

### 本机环境

- 逐项列出 `ffmpeg` / `ffprobe` / `python` 的「已找到 / 未找到」与版本说明。
- **一键配置运行环境**：自动下载安装 `ffmpeg` / `ffprobe`（约 25 MB，需要联网），完成后把路径写入设置
  并重新检测；下载期间按钮会保持禁用，网络慢时可能要等几分钟。**这个按钮只在 macOS 上出现**；
  Windows / Linux 上同一位置显示的是手动安装指引（`winget install Gyan.FFmpeg` /
  `sudo apt install ffmpeg`），装好后再用下面的「ffprobe 路径」指定位置。
- **重新检测**：立刻再跑一遍环境探测。
- **ffprobe 路径（高级）**：手动指定可执行文件位置；留空则由应用按「设置里的路径 → 安装目录 → 系统
  `PATH`」自动查找。改完保存设置会自动重新检测。

### 内容模型（ASR / OCR）

- 深度处理的材料线程依赖两项本机能力：**ASR** 把对白转成字幕，**OCR** 识别画面底部文字。
- ASR 支持 `openai-whisper` CLI 与 `whisper.cpp` CLI。whisper.cpp 必须填**模型文件路径**
  （如 `ggml-large-v3-turbo.bin`）；openai-whisper 填模型名（如 `small`）。
- OCR 使用 Tesseract，必须安装 `chi_sim` 中文语言包；检测会执行 `--list-langs` 核对。
- 「剧情抽样集数」默认 4，最多 16。抽样越多理解越完整，但 ASR/OCR/模型耗时也越长。
- 「深度处理时自动生成材料」默认开启；关闭后深度处理只做重组 + 微帧，不调用 ASR/OCR/LLM。
- 材料证据（音频、SRT、OCR 结果、`content.json`）落在输出目录的 `.material-content/`，
  汇总结果在 `material-manifest.json`；海报与过程图直接落在输出目录。

### 关于

显示版本号，并说明所有数据只保存在本机、不做账号与云端同步。

## 10. 常见问题与排错

| 现象 | 原因与处理 |
| --- | --- |
| 顶部横幅提示「运行环境未就绪」 | macOS：点横幅上的「一键配置运行环境」自动下载安装（约 25 MB，需要联网）。Windows / Linux：按横幅给出的命令手动安装 FFmpeg（含 `ffprobe`）并确保在 `PATH` 中 |
| 右上角提示「缺少 ffmpeg / ffprobe」 | 点标签或顶部横幅；或在「设置 → 本机环境」里指定 `ffprobe` 路径后保存 |
| 一键配置后仍提示未就绪 | 应用装完会自动重测；若仍缺，检查是否杀软拦截下载，或手动在「设置 → 本机环境」填 `ffprobe` 路径并保存 |
| 找不到「一键配置运行环境」按钮 | 这是刻意隐藏的：该功能只有 macOS 有可用下载源，其他平台请按横幅/设置页给出的命令手动安装 |
| 「探测并检查」失败并提到 ffprobe/启动/PATH | 同上；错误信息里会点名本机缺的是哪个工具 |
| 「请先选择剧集素材根目录」 | 先填/选根目录再点扫描 |
| 提示「报审包目录已存在」 | 换一个输出目录，或先把旧报审包移走/改名（不会覆盖已有材料） |
| 「输出目录不能是素材目录」 | 转码输出不能写回素材目录；清空让应用写到剧目目录下的子目录，或另选目录 |
| 「输出视频不能与输入视频相同」 | 擦除的输入输出必须不同，改输出文件名 |
| 改名按钮是灰的 | 需要先「预览改名计划」，且已有 `待改名` 项、当前没有别的任务在跑 |
| 提示「已经有任务在进行」 | 上一个耗时操作还没结束，等进度条走完再点 |
| 某个按钮点了没反应 | 长任务开始后所有耗时按钮会统一置灰，这是防止重复执行，不是卡住 |
| 检查结果长期是 `尚未探测` | 只扫了目录没点「探测并检查」，或探测失败（看失败原因那一行） |
| 码率修复后仍提示低于安全线 | 修复结果已变化，需要重新「检测码率」；个别失败项会在结果里列出原因 |
| 「探测不到码率」 | 该文件本身没有可用码率信息，需要人工确认 |

如果应用无响应：先等进度条结束（重编码与擦除可能数分钟）；确认无任务后再操作。

## 11. 已知限制

- 界面**不做**素材的剪切/合成，转码与重编码只做规范化与分集重组；时长/内容层面的修改请回剪辑软件。
- 「平台材料要求」是内置示例档案，不是官方规范；请替换为平台方最新要求后再使用。
- 擦除是实验能力：小掩码（角标/窄字幕条）精度最高，大面积或复杂背景需要人工抽查；
  缺少模型 worker 时部分后端不可用。
- 擦除进度的粒度是**每 30 帧一条**（管线按片段上报），不是逐帧；进度条会成段往前走。
  另外阶段内还没拿到总量时（素材未写 `nb_frames` 等）会先按不确定进度显示，拿到帧数后自动切换。
- 剪映草稿格式随剪映版本变化，读回功能可能受版本影响。
- 报审包生成不做增量更新：目标目录已存在就拒绝，需要你显式换目录。
- 检查规则可配置，但**规则再严也代替不了人工复核**：`材料可用` 只表示无失败项。

## 12. 隐私与合规边界

- 应用只在两种情况下访问网络：① 启动本机 `ffprobe` / `ffmpeg` 等外部进程（不联网）；② 你**主动点击**「一键配置运行环境」时下载官方 ffmpeg 压缩包。素材与报告始终不上传、不含云端同步。
- 设置里填写的公司、联系方式等只写入本机报审包与本地配置。
- 剧备只整理**使用者提供的真实材料**，固定包含内容权属声明模板，但**不伪造**签名、印章或时间戳；
  `manifest.json` 是本地完整性清单，不是官方审核回执。
- 擦除功能仅限自有素材；不提供 DRM 绕过，也不处理他人作品的版权标识。
- 本项目定位为技术学习与交流的示例，文中的报审格式、平台要求与发布流程都不构成合规或法律意见。

    生成报审包

    本地生成

    「本次运行覆盖」只在这一次生效；留空时写到「剧目目录/报审包」。

    合规说明：剧备只整理使用者提供的真实材料，不伪造签名、印章或时间戳；报审包固定包含内容权属声明模板。

    转码处理

    两种模式都输出到新目录，绝不改动原素材；全剧重编码，耗时较长。点「停止转码」会立刻终止并删除本次输出目录。

    转码建议与批量规范化

    对照目标规格逐集给出「是否需要转码 + 原因 + ffmpeg 命令」。只产出建议，不会自动转码。

    尚未选择剧目——请先到「剧目库」扫描并点选一部剧。

    字幕擦除

    实验功能 · 仅限自有素材

    为草稿准备干净视频：擦除硬字幕与角标，结果按确认流自动校验。

    高级参数（膨胀 / 羽化 / worker / 截取）

    只处理自有素材的硬字幕与角标；擦除结果按确认流自动校验（退出码 0 通过 / 3 需人工抽查 / 2 校验失败）。 本功能不提供 DRM 绕过能力，也不处理他人作品的版权标识。

    剪映草稿

    导出分集顺序与时长到剪映草稿目录，或把草稿时间线读回来核对。草稿格式随剪映版本变化。

    V5 去重验证

    技术验证

    对照 Grove Max 逆向文档的两轮编码端到端验证：母版去重 → overlay（AI 角标 / 剧名水印）→ 成片（机型伪装元数据）。 同一输出目录 + 同参数重跑时，已完成的步骤按 checkpoint 自动跳过（断点续跑）。 依赖仓库内 cloud 虚拟环境，仅用于技术验证，不是正式去重功能。

    尚未选择剧目——请先到「剧目库」扫描并点选一部剧。

    该用哪个工具？

    1. 只想先看看要改什么：用「转码 → 转码建议」，它只出建议，不动文件。
    2. 只是码率不达标：用「码率修复」，会就地重编码不达标的分集（替换原文件）。
    3. 要改时长、顺序或分集数：用「转码 → 执行转码」，结果写到新目录。
    4. 文件名不统一：先做「批量改名」，再跑上面的检查（集号解析依赖文件名）。
    批量改名

    按解析出的集号统一为「剧名 - 第NN集」。先预览完整计划，确认后执行； 目标名冲突或重复时整体拒绝，不会改到一半。

    码率修复

    逐集检测视频码率，只重编码低于安全线的分集到安全范围；原文件经临时文件原子替换。 重编码需要 ffmpeg，耗时与视频长度成正比。

    报审包差异对比

    读两份报审包的 manifest.json，列出新增 / 移除 / 修改的文件（不读取素材内容）。

    平台材料要求（示例档案）

    内置档案是学习示例，不是任何平台的官方规范；接入真实业务前请替换为平台方最新规范。

    发布素材文案（本地 CSV）

    生成并编辑「挂载文案.csv」。此功能只处理本地文案和状态，不连接第三方平台或读取登录会话。

    dry-run 只校验文案和 ready 状态，不连接平台、不模拟上传；预览中的“可提交”不代表已提交。
